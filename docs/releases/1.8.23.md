# Sky Omega 1.8.23 — Mercury: DELETE ends a fact's valid time

**Released:** 2026-10-27
**Version bump:** `Directory.Build.props` → 1.8.23 (with these notes)
**Predecessor:** [Sky Omega 1.8.22](1.8.22.md) — Mercury: one pattern path for SPARQL UPDATE.

## Headline

On a Cognitive store (the default profile, and the Mercury MCP memory store), a SPARQL delete removed the fact from
every point-in-time view, including views from before the delete. Rewriting a status from `"open"` to `"fixed"`
left no status at all `AS OF` the morning before. That contradicted [ADR-001](../adrs/mercury/ADR-001-compaction.md)
and the stated design: a delete closes the fact's valid time.

Now a delete ends the fact: its version gets the delete's time as its `ValidTo`, so `AS OF` an earlier time still
returns it. "This was recorded in error" is a separate operation, Retract
([ADR-054](../adrs/mercury/ADR-054-delete-ends-valid-time.md)). A new `mercury --repair-deletes` repairs the history
that earlier deletes erased.

## Fixed

- **A delete erased history.** `DeleteCurrent` (every SPARQL delete: DELETE DATA, DELETE templates, DELETE WHERE,
  CLEAR, DROP, MOVE) flagged the entry as deleted and left `ValidTo` open. `AS OF` and `DURING` skip flagged entries
  at every time. It now ends the version that holds at the delete's time.
- **A re-insert after a delete was silently dropped.** `INSERT x`, then `DELETE x`, then `INSERT x` reported 1
  affected, but `x` was not stored: the insert's duplicate check counted the deleted entry as current. A re-insert now
  creates a new version, after a delete and after a retraction alike.
- **DELETE hit the wrong version.** For a quad with an earlier, closed version and a current one, DELETE flagged the
  earlier version and the quad stayed current. The delete also searched only one leaf page.
- **Delete counts were wrong.** A delete counted a triple whenever its atoms existed, so deleting an already-deleted
  triple reported 1. Counts are now the versions that ended.
- **`DELETE { x } INSERT { x }` split a fact's history.** A quad in both sets now leaves both, so its version stays
  unbroken.
- **Pruning with `PreserveAll` brought retracted facts back.** They were copied into the target as plain adds; they are
  now retracted there too.
- **WAL recovery skipped operations it didn't know.** It now throws, naming the operation, so a log written by a newer
  Mercury fails loudly instead of losing writes.

## Changed

- **WAL:** operation 2 is renamed `Retract`, and a new operation `End = 5` names the version it ends by its
  `ValidFrom`. Replaying a log is idempotent, including when a fact is deleted and re-inserted in the same millisecond.
  Delete records written before 1.8.23 (`[MinValue, MaxValue]`) replay with their old meaning.
- **API:** `QuadStore.Delete`/`DeleteBatched` (with an interval) are renamed `Retract`/`RetractBatched`, and they
  match the version's exact interval. `DeleteCurrent`/`DeleteCurrentBatched` keep their names and now end the fact.
  `ResolvedTemporalQuad` gains `RetractedAt`.
- **A replayed Add counts as a duplicate when its `ValidFrom` and transaction time match.** It used to need all seven
  key fields to match, but an End may since have shortened `ValidTo`, and the replay must not bring the version back.

## Added

- `mercury --repair-deletes [--dry-run] [--restore <graph>@<time>]` (ADR-054 D7). Each entry flagged by an earlier
  delete becomes what an End would have written: `ValidTo` = its deletion time. The exception is a deletion event named
  with `--restore`, where the delete itself was the mistake; those facts are restored as current. The dry run prints
  every deletion event with its entries. Run it with `mercury-mcp` stopped.

## Validation

- `DeleteEndsValidTimeTests` (17): End and `AS OF`, several versions, versions across leaf pages, counts, batches,
  Retract with adjacent versions, re-insert after End and after Retract, the SPARQL status rewrite, the no-op rewrite,
  WAL replay (Add + End opened twice, same-millisecond re-insert, a pre-1.8.23 record, an unknown operation), and the
  repair. Two new pruning tests.
- Mercury.Tests 4,776 passed, 7 skipped, 0 failed (W3C conformance included); Mercury.Solid.Tests 25/25;
  SkyOmega.Bcl.Tests 12/12.
- **On a copy of the Mercury MCP memory pool:**
  - The dry run found 323 flagged entries in 96 deletion events.
  - The repair ended 204 entries and restored the 119 deleted by mistake on 2026-05-30.
  - Afterwards, a bug's status `AS OF` 2026-10-27T06:00Z is `"open"` and now `"fixed"`.

## Known issues

- [ADR-053](../adrs/mercury/ADR-053-one-rdf-term-one-atom.md) (Proposed): writers store some RDF terms in more than one
  form. Examples: `INSERT DATA` stores `1` bare, and `^^xsd:integer` unexpanded.
- A query with GRAPH inside a nested group (`{ … } UNION { GRAPH ?g { … } }`) fails to parse: queries still run the
  legacy WHERE parser first (proposed ADR-055).
- Carried over: one debugger thread leaks per ended DrHook session on Linux; Windows lacks `RequestExit`.
