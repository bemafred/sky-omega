# Sky Omega 1.8.13 — DrHook runs on Linux

**Released:** 2026-10-25
**Version bump:** `Directory.Build.props` → 1.8.13 (`162fc43`)
**Predecessor:** [Sky Omega 1.8.12](1.8.12.md) — Mercury: every operation of a chained update runs.

## Headline

DrHook's first run on Linux failed completely. On zbook (Ubuntu 26.04.1 LTS, x86_64, glibc 2.43, Ubuntu's own
distro-built .NET SDK 10.0.113), every integration test failed or hung, and every VSTest run left processes behind.
From 1.8.13, DrHook launches, attaches and cleans up on Linux x64 with glibc, and the integration suite passes there as
it does on macOS.

The full investigation is [finding 92](../../poc/drhook-engine/findings/92-linux-first-run.md). It is the first Linux
data point for [ADR-007](../adrs/drhook/ADR-007-teardown-concurrency-test-debug.md) Phase 9, the cross-platform
validation campaign.

## Fixed

- **DrHook could not find `libdbgshim` on a distro-built .NET.** Ubuntu's .NET reports the RID `ubuntu.26.04-x64`, and
  no `Microsoft.Diagnostics.DbgShim` package ships under that name. `DbgShim.CandidateRids` now tries the reported RID
  and then the portable one (`linux-x64`). The csproj selects packages by `NETCoreSdkPortableRuntimeIdentifier`.
- **Launching a target corrupted memory on Linux.** `PosixSpawn` was written for macOS. On glibc the spawn attribute
  and file-action types are 336- and 80-byte structs, not pointers, so initialising them overwrote the stack and the
  launch spun forever. The flag meant to start the child suspended means "new session" on glibc, and signal 19 is
  `SIGSTOP` there, not `SIGCONT`. Each platform now declares its own types exactly. macOS is unchanged. On Linux the
  child holds itself (`kill -STOP $$; exec "$0" "$@"`) until DrHook has armed the runtime-startup callback, then
  resumes on `SIGCONT` 18. `exec` keeps the pid, so the target runs nothing before the callback is armed.
- **VSTest test runs leaked their whole process tree.** The harness's group kill needs `set -m`, which Ubuntu's
  `/bin/sh` (dash) refuses without a terminal. Targets are now spawned under `/bin/bash`.
- **Two VSTest tests depended on event ordering.** They assumed the attach always lands before the test host's debug
  hold ([finding 91](../../poc/drhook-engine/findings/91-vstest-host-debug-attach-race.md)), and now accept either
  order.

## Changed

- **Launch on musl is refused** with an explicit error until its spawn types are measured on a musl system. Attach
  is unaffected.
- **Each integration test has a 120 s limit** (`testconfig.json`). The engine's native calls have no timeouts of their
  own, so a hang used to stall the whole run; now it fails with the test's name.

## Follow-up after the bump: the timeout leaked targets

`c0c76c6` landed after the version bump and changes only the test harness. When MSTest abandons a test at its
timeout, the test's own cleanup never runs, so the targets it spawned kept running. Every spawn now runs in its own
process group and is recorded. An `[AssemblyCleanup]` step, which still runs after an abandoned test, kills every
recorded group.

## Validation

- **zbook:** engine unit tests 167/167. Integration suite: 69 of 70 full runs passed 16/16, with no leftover
  processes. The 3 launch tests run alone passed 60/60.
- **Mac (macOS 27, M5):** engine unit tests 167/167. Integration suite 5 × 16/16, no leftover processes.
- **The timeout follow-up:** a test abandoned at a deliberately short limit left nothing running on either machine,
  across 3 spawn shapes and 3 limits. Full suite 5 × 16/16 on each machine.

## Known issues

- **One unreproduced failure.** In one of the first five full runs on zbook, `CaptureState_AtBreakpoint` got no
  entry-module hold stop within 20 s. It did not recur in the next 65 runs. The test now reports the target's state
  and every event received, so a recurrence can be diagnosed from the failure alone.
- **A process whose executable was deleted broke the process listing on Linux.** Found after this release:
  [finding 93](../../poc/drhook-engine/findings/93-deleted-executable-process-listing.md), fixed in
  [1.8.14](1.8.14.md).
