# Sky Omega 1.8.20 — DrHook: a Windows debuggee's console is isolated; a Linux host crash fixed

**Released:** 2026-10-27
**Version bump:** `Directory.Build.props` → 1.8.20 (with these notes)
**Predecessor:** [Sky Omega 1.8.19](1.8.19.md) — DrHook on Windows arm64: the full suite passes.

## Headline

On Windows, a target launched by DrHook shared the debugger's stdin, stdout and stderr. Under `drhook-mcp` those are
the JSON-RPC channel: probe 64 saw the target write into it and **read the client's request line**. The Windows
launch now starts the target itself, as POSIX has done since finding 75
([finding 97](../../poc/drhook-engine/findings/97-windows-launch-stdio-isolation.md)).

Running the suite more often on Linux arm64 exposed a host crash that 1.8.19 already had: freeing libdbgshim left
thread-exit hooks pointing into unmapped memory
([finding 98](../../poc/drhook-engine/findings/98-dbgshim-unload-tls-destructor-segv.md)).

## Fixed

- **A launched Windows debuggee shared the host's standard streams.** `Interop/WindowsSpawn.cs` starts it suspended
  with `CreateProcessW`. stdin is `NUL`, and stdout and stderr are DrHook-owned pipes drained to the event sink.
  Only those three handles are inherited. The child has its own console with no window.
- **Launch with environment overrides threw `PlatformNotSupportedException` on Windows.** It works now. Names are
  case-insensitive, so an override replaces an entry of any case.
- **Windows argument quoting** follows the `CommandLineToArgvW` rules. A path ending in `\` used to break.
- **The test host could crash with SIGSEGV on Linux** (about 1 run in 8 on arm64). libdbgshim's embedded PAL registers
  pthread keys whose destructors live in the library. `DbgShim.Dispose` freed the library, and a thread that had
  called into it crashed when it exited later. libdbgshim is now loaded once per process and never freed.

## Added

- Probes 64 (launch stdio isolation, run as an MCP-like host) and 65 (dbgshim unload and thread exit).
- `ConsoleIsolationTest` (integration, every platform), `WindowsSpawnTests` and `DbgShimLifetimeTests` (unit). The
  lifetime test fails with `Dispose` freeing the library.

## Validation

- Probe 64 on omega-windows: isolated (it leaked before the fix); the macOS control stays isolated.
- Probe 65, library freed vs kept: Linux arm64 5/5 crashed vs 0/5; Linux x64 3/3 vs 0/3; macOS and Windows 0 either way.
- DrHook integration: omega-windows 17 passed / 2 skipped in 3 of 3 runs; omega (macOS) 18 / 1 in 3 of 3; elite
  (Linux x64) 18 / 1 in 2 of 2. No leftover processes.
- DrHook.Engine.Tests: Windows 178 passed / 5 POSIX-only skipped; macOS and Linux 183 / 1.

## Known issues

- **A second host crash on Linux arm64 is open** (finding 99, being investigated). With the fix, omega-ubuntu still
  crashed in 2 of 12 integration runs, both in the same place in a thread started by `libmscordbi`. One run also
  timed out a VSTest flood test at 120 s.
- Windows still lacks `RequestExit` (graceful stop). The probe corpus and `drhook-mcp` have not run on Windows yet,
  and nothing has run on Windows x64 ([ADR-007](../adrs/drhook/ADR-007-teardown-concurrency-test-debug.md) Phase 9).
- Carried over: `dotnet test` does not show xunit's diagnostic messages; `dotnet test` exits 0 when its front end gets
  SIGTERM; NCrunch is unverified with xunit.v3.
