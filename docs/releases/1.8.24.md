# Sky Omega 1.8.24 — Mercury: every result row keeps its own column names

**Released:** 2026-10-27
**Version bump:** `Directory.Build.props` → 1.8.24 (with these notes)
**Predecessor:** [Sky Omega 1.8.23](1.8.23.md) — Mercury: DELETE ends a fact's valid time.

## Headline

`SparqlEngine.Query` (behind `mercury_query`, the HTTP endpoint and the CLI) took a SELECT result's column names from
the first row and read every later row by position. When the first row lacked a value, other rows lost theirs or had
them filed under another variable's name. An `OPTIONAL` whose first row was unbound dropped that column for every
row, and rows from a `UNION` branch came back under the other branch's names. Each row is now named by its own
bindings.

## Fixed

- **OPTIONAL values vanished when the first row had none.** The column was missing from the header and from every row.
- **UNION rows got the wrong names.** A row from a branch binding other variables was read by position under the first
  row's names.
- **`SELECT *` listed only the first row's variables.** It now lists every variable some row binds, in the order the
  query first mentions it.
- **`$x` variables came back as `var0`.** A `$` variable in a triple pattern is now named `x`.

## Changed

- An explicit `SELECT` returns only its projected variables and aggregate aliases in each row, whatever else the WHERE
  binds.

## Validation

- `ResultColumnNamingTests` (7): OPTIONAL with the first row unbound, UNION with different variables, `SELECT *` over
  a disjoint UNION and with OPTIONAL, `$` variables, unprojected variables, an aggregate alias. The five that cover the
  defects failed before the fix.
- Mercury.Tests 4,783 passed, 7 skipped, 0 failed (W3C conformance included); Mercury.Solid.Tests 25/25.

## Known issues

- [ADR-055](../adrs/mercury/ADR-055-query-where-one-parse.md) (Proposed): a query's WHERE is still parsed twice, so
  GRAPH inside a nested group fails to parse, and `SELECT *` omits a variable that no row binds.
- `$x` is recognized only in triple patterns and ORDER BY: `SELECT $s …` returns no rows and `VALUES $x` fails to parse
  (folded into ADR-055 D1).
- [ADR-053](../adrs/mercury/ADR-053-one-rdf-term-one-atom.md) (Proposed): writers store some RDF terms in more than one
  form.
- Carried over: one debugger thread leaks per ended DrHook session on Linux; Windows lacks `RequestExit`.
