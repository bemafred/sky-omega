# Sky Omega 1.8.42 — DrHook: the views are tools that wait for a session and show it from its start. Mercury: NOW() is one value per query; date arithmetic

**Released:** 2026-11-14
**Version bump:** `Directory.Build.props` → 1.8.42 (with these notes)
**Predecessor:** [Sky Omega 1.8.41](1.8.41.md) — Mercury: the W3C suite cannot lose a test silently; a literal is
well-formed by one rule in every format. DrHook: a session's end and a failed launch say what happened; the snapshot
gives stacks and thread states.

## Headline

**DrHook: a human can leave a view of the debug session running.** `drhook-viz-tui` and `drhook-viz-console` are
global tools now, installed by `tools/install-tools.sh`. The dashboard can be started before any session: it waits,
connects when a session starts, keeps the last picture when it ends, and connects to the next one. A view that
connects after a session started is sent what the session emitted until then, so it shows the hypothesis the session
was launched with and the target's output from its first line.

**Mercury: `NOW()` is one value per query execution**, as SPARQL 1.1 §17.4.5.1 requires. It was read at every call:
`BIND` over 1,000 rows gave 773 values, and `FILTER(?t = NOW())` kept none of them.

**Mercury: a query can ask for what was recorded in the last week.** A dateTime or a date plus or minus a duration,
and the difference of two of them, are evaluated (XPath 3.1's date and time operators, as an extension).

## DrHook: the views are installable

| Command | Package | What it is |
| --- | --- | --- |
| `drhook-viz-tui` | `SkyOmega.DrHook.Viz.Tui` | The full-screen dashboard |
| `drhook-viz-console` | `SkyOmega.DrHook.Viz.Console` | The session as a text tail |

Both are in `tools/install-tools.sh` and `tools/install-tools.ps1`, and both answer `-v` / `--version`. They are
started by a human and connect to the session's rendezvous socket. They are not part of the MCP surface, and closing
one never affects the session.

## DrHook: a view outlives a session

- **The dashboard always waits.** Started with no session up, it shows `waiting for a session (q to quit)` and looks
  for the socket twice a second. At a session's end it keeps the last picture with
  `session ended, waiting for the next (q to quit)` until the next session replaces it.
- **The console view waits with `--follow` (`-f`).** Without it the view prints one session and exits, and exits at
  once when no session is up, as before.
- **The library:** `DebugStateClientOptions.Reconnect` and `ReconnectDelay` (500 ms by default). The view is told once
  that there is no session, not at every attempt, and the model is reset at each new connection. A missing socket
  reads `no session (no socket at …)`; Linux reported it as "Cannot assign requested address".

## DrHook: a view that connects late is shown the session from its start

Before this release a connecting view got the current snapshot and then the live stream. The snapshot carries the
stream counts and not the records, and a hypothesis or an event is in no snapshot. A dashboard that was already
waiting connects a moment after the session starts, so it never showed a target's output up to its first stop.

- **`DebugStateServer` keeps the running session's most recent deltas**, 1,000 by default (`replayCapacity`; 0 turns
  the replay off). A connecting view is sent them, oldest first, then the current snapshot, then the live stream.
  The history is emptied when the session ends, so one session's deltas are never replayed into the next.
  `ReplayDropped` counts what fell off the history.
- **Nothing is sent twice and nothing is left out at the join.** A sequence number is handed out in the same critical
  section that stores its message, and the join captures the history, the snapshot and its sequence number in one
  step, with the client list held until the view is registered. Before, a snapshot published between a view's connect
  and its registration could miss that view. The sequence numbers on one connection only rise.
- **The history is taken within the send timeout, or the view is dropped.** The other views wait while one view is
  sent the history, so it has the time one message has (2 s). Added after the first CI run of this release: on macOS
  x64 a test's deliberately slow readers held the other views back for more than five seconds.
- **The session's own hypothesis opens the braid.** `drhook_launch` and `drhook_attach` now emit the hypothesis they
  were given; it was kept for the session's summary and never reached a view.
- **`DrHook.Capture` records the whole session** when it connects late, for the same reason.

The wire format is unchanged: the replayed deltas are ordinary `delta` lines. A view built against 1.8.41 works; it
receives deltas before its first snapshot, which a view that connected before the first stop already did.

## Fixed: Mercury

- **`NOW()` is one value per query execution** (`531a24f`). The time is read once when the executor is made and
  passed to every evaluator. Measured before the fix: two `NOW()` in one row differed by 300 ns, `BIND` over 1,000
  rows gave 773 values, `FILTER(?t = NOW())` kept 0 of 1,000 rows, and an `INSERT` over 1,000 rows wrote 850 values.
- **A temp directory whose lock file names no process is not swept** (`5b1d8c1`). `TempPath.CleanupStale` deleted a
  directory at once when its lock file was empty or did not parse, and `MarkOwnership` creates the file before it
  writes it. Such a directory is now treated like one with no lock file: in use for 24 hours after it was created.
  This was read from the code after a CI failure on Linux x64; the failure itself was not reproduced.

## Added: Mercury

- **Date arithmetic** (`305ea5b`): a dateTime or date plus or minus an `xsd:dayTimeDuration` or
  `xsd:yearMonthDuration`; a dateTime minus a dateTime and a date minus a date; durations compared by value. So
  `FILTER(?created >= NOW() - "P7D"^^xsd:dayTimeDuration)` selects the last week. `AS OF` and `DURING` do not select
  by recency, and the SPARQL reference now says what they select.

## Changed: breaking for C# callers of the storage API

- `ValidFrom` and `ValidTo` are named `MemorizedAt` and `ForgottenAt` (`6bc9602`, ADR-061 D11).
- Five attributes of the Cognitive entry carry the `Legacy` prefix (`be1899f`, ADR-061 D15):
  `LegacyTransactionTime`, `LegacyCreatedAt`, `LegacyModifiedAt`, `LegacyVersion`, `LegacyIsDeleted`. Two of them are
  on the public `ResolvedTemporalQuad`.

Both are renames. No behaviour changed and no stored byte moved: a store written by 1.8.41 is read as it is.

- `poc/avalonia-term`: 30 passed, 1 skipped (needs vim), after the rename.
- Full suite on zbook (Linux x64): 6,875 tests, 0 failed, 159 skipped. Not run on omega for this release; the
  Mercury changes carry the runs named in their commits.
- Live run on zbook with the installed 1.8.42 tools: `drhook-viz-tui` started first and waiting, one session driven
  through `drhook-mcp` with its breakpoint on the target's last line. The dashboard showed the three lines the target
  printed before that stop. A `drhook-viz-console` started after the stop printed the launch's hypothesis, the events
  and the three lines, and then the snapshot. `q` restored the terminal and no process was left.

## Known, not fixed

- The dashboard's braid pane has six rows, and a session's module-load events push the hypotheses out of it.
- After a session ends the dashboard's title still reads the last stop reason; there is no final snapshot.
- The views were not run on Windows or macOS in this release. CI runs their tests on all six platforms.
- A target that dies during a mscordbi request still leaves the DrHook debugger unusable in its process, until the
  MCP server restarts (finding 105). The worker process (ADR-016 Step 5) is not built yet.
