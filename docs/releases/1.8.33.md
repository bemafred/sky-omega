# Sky Omega 1.8.33 — Mercury: IRIs and constants as their terms

**Released:** 2026-10-29
**Version bump:** `Directory.Build.props` → 1.8.33 (with these notes)
**Predecessor:** [Sky Omega 1.8.32](1.8.32.md) — Mercury: grouping and aggregates by §18.2.4 and §18.5.

## Headline

**Three fixes in how Mercury reads what a query or a document writes:**
- an IRIREF's character rule holds for escaped characters too;
- a query's relative IRIs are resolved against its BASE;
- a constant is stored and matched as the RDF term it denotes.

**20 W3C known failures pass**, so 11 remain (31 at 1.8.32):
- 9 in SPARQL 1.0 (22 at 1.8.32);
- 2 in RDF/XML.

None remains in Turtle, TriG, N-Triples or N-Quads.

## Changed: what is accepted and returned

These changes in behavior follow the specs. Each was wrong before.

- **An escape of a character IRIREF excludes is a syntax error** in Turtle, TriG, N-Triples and N-Quads. Before, any
  escape was accepted:
  - an escaped space, `<http://ex/s\u0020>`, gave an IRI with a space in it;
  - so did an escaped `<`, `>`, `"`, `{`, `}`, `|`, `^`, `` ` `` or backslash.
- **Two readers accepted raw characters IRIREF excludes:**
  - N-Quads accepted a written `<`;
  - TriG checked only whitespace, so a written `{`, `}`, `|`, `^`, `"` or `` ` `` was accepted.
- **A query's relative IRIs are resolved against its BASE** (§4.1.1.1). `BASE <http://ex/x/> SELECT * { <a> ?p ?v }`
  reads `<http://ex/x/a>`. Before, it read an IRI named `a`, and `PREFIX : <>` made `:x` the IRI `x`.
- **A constant is the term it denotes**, in a pattern, VALUES, a CONSTRUCT template or Update data:
  - `'''x'''`, `'x'` and `"""x"""` are the literal `"x"`;
  - `"456."^^xsd:decimal` expands its datatype;
  - `5` in a CONSTRUCT template is `"5"^^xsd:integer`. It was the untyped token `5`.
- **`:p +5` is the predicate `:p` with the object `"+5"^^xsd:integer`,** not the path `:p+` with the object `5`.
  SPARQL matches the longest token (§19.8). Likewise `?1` is a variable, not `:p?` followed by `1`.

## Fixed

### IRIREF, in every reader

- **One character class,** `RdfIri.IsIriRefCharacter`, beside the shared `HasScheme`. It covers
  `[^#x00-#x20<>"{}|^`\]` (Turtle and TriG [18], N-Triples and N-Quads [8]).
- **Every reader applies it to a written and an escaped character alike:** Turtle's two IRI loops, N-Triples,
  N-Quads and TriG. SPARQL's IRI scan applies it to written characters, since a SPARQL IRI has no escapes. Before,
  five readers each wrote the class out, and they had drifted apart.
- **JSON-LD is left as it is.** Its IRI check tests whether a value is a well-formed IRI under RFC 3987, which is a
  different rule.
- W3C turtle-syntax-bad-uri-escape-01 to -03 and trig-syntax-bad-uri-escape-01 to -04 now pass.

### BASE

- **`SparqlParser.ResolveAgainstBase` resolves a query's relative IRIs before it is parsed.** It writes every
  relative IRI as its absolute IRI (RFC 3986 §5.2), so the parser and the executor see absolute IRIs only. That
  covers patterns, FILTER and BIND constants, datatypes, VALUES, CONSTRUCT templates, Update data, FROM, GRAPH and
  SERVICE. A SERVICE request then carries absolute IRIs.
- **BASE declarations apply in order:**
  - each BASE sets the base for the text after it, and a relative BASE resolves against the one before it;
  - a PREFIX resolves against the base where it is declared;
  - each operation in a `;`-separated Update uses its own BASE.
- **IRIs are found with the parser's token rule,** so a `<` inside a literal or a comment, or used as less-than, is
  left alone. A query with no BASE is not touched.
- **`SparqlEngine` applies it to every query, update and EXPLAIN.** Code that builds `SparqlParser` and
  `QueryExecutor` itself must apply it too. The W3C harness does, where it reads each test's text.
- W3C base-prefix-1, -2, -4, -5 and -6 now pass.

### Constants

- **Five sites turned a constant into a term, each with a partial rule:**
  - the scan's two resolvers decoded only a short double-quoted literal;
  - Update data stored a number as written;
  - VALUES copied every quoted form as written;
  - a CONSTRUCT template copied every constant as written.
- **`LiteralForm.StoredTerm` is now the one rule.** It reads a literal, number or boolean with the expression
  evaluator's constant reader (ADR-056) and writes it with `Value.Term()`. So it is the same term a FILTER or BIND
  reads. A constant already in its stored form, an IRI or a blank node is returned as it is, with no allocation.
- **`LiteralForm.Canonicalize` is deleted.** Its 38 tests now test `StoredTerm`, with the same expectations, and
  all pass.
- **One reader of a path modifier,** `PathModAt`. It replaces five places that each wrote the test out.
- W3C quotes-1 to -4, term-6 to -8 and open-eq-02 now pass.

## Stack

Every query shape still completes in 23 KB. That was measured after the IRIREF change; the other two add no
recursive frames.

## Tests and conformance

- New tests:
  - `IriRefCharacterTests` (19). Its 15 malformed documents were all accepted by the 1.8.31 readers.
  - `BaseResolutionTests` (12)
  - `ConstantTermTests` (16)

  - ADR-053 term identity (3): a simple literal and its `xsd:string` form are two atoms; a pattern constant matches a

  - XMLLiteral exclusive canonicalization in RDF/XML (2).
