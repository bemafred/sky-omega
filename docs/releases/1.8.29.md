# Sky Omega 1.8.29 — Mercury: the SPARQL 1.0 suite runs, and an expression value is the RDF term

**Released:** 2026-10-28
**Version bump:** `Directory.Build.props` → 1.8.29 (with these notes)
**Predecessor:** [Sky Omega 1.8.28](1.8.28.md) — Mercury: DESCRIBE reads every graph.

## Headline

**The SPARQL 1.0 W3C suite runs, and it found work.**
- Mercury had run only the SPARQL 1.1 manifests. ADR-010 scoped conformance to 1.1, on the assumption, never written
  down, that 1.1 covers 1.0. It doesn't: the 1.0 manifests hold 483 query tests, many with no 1.1 counterpart.
- Wired in, they passed 359 of 483. This release brings that to **427 of 483**.
- Each of the 56 that remain is a known failure listed with its cause. They run as skipped tests, so the gap stays
  visible.

**The largest fix is [ADR-056](../adrs/mercury/ADR-056-expression-value-is-the-term.md): an expression value is the
RDF term it was read from.**
- The evaluator kept only a number for a numeric term, so `"01"^^xsd:short` became the long 1.
- Comparisons had no error outcome, so `!=` and `!` kept rows whose comparison has no answer.
- ADR-056 is the evaluator part of [ADR-053](../adrs/mercury/ADR-053-one-rdf-term-one-atom.md), split off because it
  changes no stored data. ADR-053 keeps the write paths and the store migration, with Q2 and Q3 open.

## Changed: what queries return

These are behavior changes. Each follows SPARQL 1.1, and each was wrong before.

- **BIND and SELECT expressions return terms.**
  - `BIND(1 + 1 AS ?x)` gives `"2"^^xsd:integer` (was `2`), and `BIND("a" AS ?x)` gives `"a"` (was `a`).
  - `BIND(?o AS ?x)` gives the stored term: `"01"^^xsd:integer` stays `"01"`.
- **No coercion of strings to numbers.** `"30" = 30` is false (a string and a number are in different value spaces),
  and `"5" + 1` is an error.
- **An undeclared datatype prefix is an error**, `xsd:` included. `xsd:` used to be expanded even when the query
  didn't declare it.
- **Comparing two IRIs with `<` is an error.** SPARQL orders only numbers, strings, booleans, dateTimes and dates.
- **Arithmetic keeps SPARQL's types.**
  - `7 / 2` is `"3.5"^^xsd:decimal` (was a double).
  - `CEIL(1.5)` is `"2.0"^^xsd:decimal`.
  - `SECONDS()` is a decimal.
  - `ROUND` rounds a half towards positive infinity: `ROUND(-2.5)` is `-2.0`.

## Fixed

### Expressions (ADR-056)

- **The term is kept.**
  - `STR`, `DATATYPE` and `sameTerm` read the stored lexical form and datatype, so `DATATYPE` of an `xsd:short` is
    `xsd:short`, and `sameTerm("01"^^xsd:integer, 1)` is false.
  - `1e3` is the double 1000; it was read as `1`, and the `e3` was left unparsed.
  - `.5` and `+1` are numbers.
- **`=` and `!=` follow the operator mapping and RDFterm-equal.**
  - A literal of an unknown datatype, or an ill-typed one, is equal only to the same term. Anything else is an error.
  - Language tags compare ignoring case.
  - A prefixed datatype in a constant (`"a"^^t:type1`) is expanded through the prologue. Only `xsd:` was.
- **Dates and dateTimes compare by value**, in XSD's partial order. A date with a timezone and one without are
  incomparable when they are within 14 hours.
- **Errors propagate.**
  - `!`, `&&`, `||`, `IN` and FILTER follow the §17.2 truth tables, through one effective boolean value.
  - `!?w` with `?w` unbound is an error, so FILTER keeps no row.
  - `LANG` and `DATATYPE` of an IRI are errors.
- **IF's condition is evaluated with the query's prefixes.** It was evaluated without them.
- **Decimal and float are types of their own.**
  - Arithmetic promotes integer → decimal → float → double.
  - `xsd:float()` makes a float, and `xsd:decimal()` a decimal.
  - `xsd:dateTime()` is a cast.
  - `xsd:string()` writes a number's or boolean's canonical form, so `xsd:string("0"^^xsd:boolean)` is "false".
- **ORDER BY orders literals by the same `<`.** It parsed any literal that looked like a number, so
  `ORDER BY STR(?o)` sorted numerically.
- **One way from a value to a binding**, for BIND, SELECT and GROUP BY expressions, sub-SELECT projection, ORDER BY
  and aggregate arguments. There were five, each its own.

### Blank nodes

- **Each loaded document's blank nodes are its own.** Two documents that each write `[ :q 1 ]` gave one node.
  - Every load is scoped: a document, an Update operation, a template solution, and BNODE()'s process. A scope's token
    is a version-7 GUID.
  - The six RDF formats share one parse, and SPARQL LOAD reads all six (it read three).
  - Solid PUT, POST and PATCH scope their documents too.
- **A template's blank nodes are new for each solution.** They were one node for all solutions.
- **A blank node is its own kind of term in an expression.** `isBlank` was false for every stored blank node, and
  `STR` returned its label.
- **A blank-node graph name** was written as `<_:…>` when named graphs were listed.

### Parsing

- **Expansions have no size limits.**
  - A collection, a property list or a sequence path kept at most 32 triples and dropped the rest without an error.
  - Join variables broke past 32 per kind.
  - The binding table dropped bindings past 64.
  - CONSTRUCT templates stopped at 16 triples.
- **One token rule finds where an expression ends.**
  - A `)` or `(` inside a string broke FILTER, BIND, SELECT expressions, aggregate arguments and HAVING.
  - `?gas` was read as the keyword AS.
- **ORDER BY takes expressions**: `(expr)`, `ASC(expr)`, `STRLEN(?o)`. It read variables only, and ignored conditions
  past 4.
- **One template grammar** for INSERT DATA, DELETE DATA, Update templates and CONSTRUCT. The DATA parser read no
  collections or blank-node property lists, and the Update rules are enforced now:
  - no variables in DATA;
  - no blank nodes in DELETE DATA, a DELETE template or DELETE WHERE;
  - no blank-node label shared by two operations' data.
- **A keyword is a whole word.** A subject like `graph:a`, `values:v` or `filter:f` was read as that clause, and
  `sum:f(` was read as SUM.
- **SERVICE** sends the prologue's prefixes with its group.

### OPTIONAL

- **Nested OPTIONAL follows LeftJoin.**
  - A variable bound only inside a nested OPTIONAL is joined after the group (W3C nested-opt-1 gave 2 rows for 1).
  - An OPTIONAL group's FILTER is evaluated on the joined row.
- **A node subject is expanded once.** `[] :p ?a ; :q ?b` gave each triple a node of its own: a cross product.

### W3C test harness

- **The SPARQL 1.0 query manifests run.** Several harness fixes came with them:
  - result sets written in RDF/XML and ordered by `rs:index` are read;
  - tests the working group did not approve are skipped;
  - REDUCED results are compared as sets;
  - files named in FROM are loaded.
- **An ASK result written as RDF (`rs:boolean`) was read as a result with no rows.** So 13 type-promotion tests were
  listed as failures Mercury gets right, and 9 passed by accident.
- **The Update syntax manifests run with the Update parser.** 13 negative tests had been accepted.
- **`W3C_RUN_KNOWN_FAILURES=1`** runs the known failures as ordinary tests.

## Known issues

- **Stored forms (ADR-053, Proposed):**
  - a constant in a pattern (`{ ?s :p "a"^^t:type1 }`) still misses a stored full-IRI datatype;
  - `"abc"` and `"abc"^^xsd:string` are stored as two atoms, so DISTINCT keeps both.
- **Read rules for earlier writers (ADR-056 D7):** the evaluator still reads a stored `^^xsd:T` datatype, and a bare
  number, as the XSD literal. ADR-053's migration removes the need. The 33 memory atoms with an empty datatype now
  give an error when compared by value.
- **Aggregates** read numbers through their own `TryParseRdfNumeric`, and SUM and AVG carry decimals as doubles.
- **The 56 remaining SPARQL 1.0 failures**, by cause:
  - invalid syntax accepted: a missing or stray DOT, a blank-node label reused in another group, a blank node as
    predicate or in FILTER;
  - long string literals in patterns;
  - relative IRIs against BASE;
  - numeric literal forms in patterns;
  - REGEX escapes and the `q` flag;
  - i18n prefixed names;
  - 9 decimal and float type-promotion tests.
- **Carried over:**
  - HAVING matches aggregates by their text;
  - DISTINCT compares rows by a 32-bit hash;
  - on Linux, one debugger thread leaks per ended DrHook session;
  - Windows lacks `RequestExit`.
