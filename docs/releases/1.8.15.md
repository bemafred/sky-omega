# Sky Omega 1.8.15 — Tests run on Microsoft.Testing.Platform

**Released:** 2026-10-26
**Version bump:** `Directory.Build.props` → 1.8.15 (with these notes)
**Predecessor:** [Sky Omega 1.8.14](1.8.14.md) — DrHook: a rebuilt target stays visible.

## Headline

`dotnet test` at the repo root runs the whole solution again. Through 1.8.14 it failed on the .NET 10 SDK, on macOS
and on Linux, before running anything:

> error : Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later.

The solution mixed two test runners. Most projects were xunit v2 on the legacy VSTest runner; the DrHook integration
suite and its MTP target were `MSTest.Sdk` apps on Microsoft.Testing.Platform (MTP). A whole-solution `dotnet test`
ran everything through VSTest, and the .NET 10 SDK refuses to run an MTP app that way. DRHOOK.md documented the
workaround: run each project on its own. That contradicted the plain `dotnet test` CLAUDE.md and CONTRIBUTING.md
prescribe.

From 1.8.15 every test project in the solution runs on MTP, the direction Microsoft is taking `dotnet test`.

## Changed

- **`global.json` selects MTP** as the `dotnet test` runner (`"test": { "runner": "Microsoft.Testing.Platform" }`).
- **The 7 xunit projects moved from xunit v2 to `xunit.v3` 4.0.2.** They are Mercury.Tests, Mercury.Solid.Tests,
  SkyOmega.Bcl.Tests, DrHook.Engine.Tests, DrHook.Viz.Tests, DrHook.Wire.Tests and DrHook.Capture.Tests.
  `Microsoft.NET.Test.Sdk`, `xunit.runner.visualstudio` and `Xunit.SkippableFact` are gone. Each project now builds
  to an executable (`OutputType=Exe`) that is also its own test runner.
- **Run-time skips use xunit.v3's own API.** `[SkippableFact]`/`[SkippableTheory]` became `[Fact]`/`[Theory]`, and
  `Skip.If`/`Skip.IfNot` became `Assert.SkipWhen`/`Assert.SkipUnless`. The same 6 JSON-LD tests skip as before.
- **Tests pass the test's cancellation token.** xunit.v3's analyzer (xUnit1051) flags calls that accept a
  `CancellationToken` but don't get `TestContext.Current.CancellationToken`. Under `TreatWarningsAsErrors` these
  are build errors, so all of them (about 450) pass it now, and a cancelled run stops faster.
- **Mercury.Tests still runs one test at a time.** The v2 `CollectionBehavior(MaxParallelThreads = 1)` is now the
  v3 `Parallelization(MaxThreads = 1)`, for the same stack-size reason (ADR-011).
- **`MSTest.Sdk` 4.2.3 → 4.5.1** for the integration suite and its MTP target, so both frameworks use the same MTP
  generation (Microsoft.Testing.Platform 2.5). Their `TestingPlatformDotnetTestSupport` property is removed. It was
  the opt-in for the pre-.NET 10 bridge, and its comment described the opposite of what it did.

## Kept: the legacy VSTest debug target

`DrHook.Engine.IntegrationTargets.Vstest` stays a classic VSTest project on purpose. Six integration tests check that
DrHook can debug the VSTest testhosts most .NET projects still use. Under MTP, `dotnet test` refuses a VSTest project,
so the target is isolated:

- It is **no longer in `SkyOmega.sln`**. The integration suite's ProjectReference still builds it.
- Its folder has **its own `global.json`**: the SDK pin, with no test runner.
- **`TargetSpawn.Vstest` starts `dotnet test` from that folder.** `dotnet` reads `global.json` from the working
  directory, so it gets the legacy runner.
- **The spawn uses the test's own build configuration**, read from the test's bin path. It no longer hard-codes
  `-c Release`, which needed a separate Release build and would fail on a fresh clone.

## Docs

- DRHOOK.md's "Running the tests" section describes the single MTP setup and the isolated VSTest target. The
  "whole-solution caveat" is gone, and the integration suite runs with `dotnet test --project …`.
- CLAUDE.md notes that `global.json` also selects the test runner.

## Validation

- **omega (macOS, M5):** solution builds with 0 warnings and 0 errors. `dotnet test` at the root: **5,006 tests,
  5,000 passed, 0 failed, 6 skipped**, in 3 m 33 s. Integration suite 17/17, also with no Release build present.
- **elite (Linux x64, Ubuntu 26.04):** solution builds with 0 warnings and 0 errors. Every project passes except two
  VSTest integration tests (see Known issues).
- Plain `dotnet test`, `--project <path>`, a positional project path and `--filter "FullyQualifiedName~…"` all work
  under MTP.

## Known issues

- **Two VSTest integration tests fail on elite:** `AttachAndOwn_VstestTestHost_BriefWork_NaturalExit` and
  `AttachAndOwn_VstestTestHost_PauseThenDisposeWithoutResume_WorkerSilentBreakOnly`. `dotnet test` doesn't exit
  within 10 s after Dispose. This predates 1.8.15: they fail the same way at 1.8.14, and also when the suite runs
  alone. zbook passes them. Under investigation.
- **NCrunch is unverified** with xunit.v3 (Windows).
- **README's SPARQL filters match no tests**, as they did under xunit v2: `--filter "W3C.Sparql.Query"`,
  `"W3C.Sparql.Update"` and `"W3C.Sparql.Syntax"`.
