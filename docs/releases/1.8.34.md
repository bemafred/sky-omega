# Sky Omega 1.8.34 — Mercury: function arguments by the spec

**Released:** 2026-10-29
**Version bump:** `Directory.Build.props` → 1.8.34 (with these notes)
**Predecessor:** [Sky Omega 1.8.33](1.8.33.md) — Mercury: IRIs and constants as their terms.

## Headline

**SPARQL's string and date functions take the arguments the spec gives them.** Before, every string function also
read an IRI's text, and the date functions read any text as a date. Both behaviors dated from the functions' first
implementation, and no commit or ADR records a decision behind them. Mercury now follows the spec. `STR()` is the
way to get an IRI's text.

**REGEX follows XPath's flags**, `q` included.

**3 W3C known failures pass**, so 8 remain (11 at 1.8.33):
- 6 in SPARQL 1.0, waiting on ADR-053 and ADR-057;
- 2 in RDF/XML (XMLLiteral canonicalization).

## Changed: what queries return

These changes in behavior follow SPARQL. Each was wrong before.

- **A string function takes a string literal** (§17.4.3): a simple literal, an `xsd:string` or a language-tagged
  literal.
  - This covers REGEX, REPLACE, CONTAINS, STRSTARTS, STRENDS, STRBEFORE, STRAFTER, SUBSTR, STRLEN, UCASE, LCASE,
    ENCODE_FOR_URI and CONCAT.
  - An IRI, a number or a literal of another datatype is a type error. `CONTAINS(?s, "x")` on an IRI keeps no row;
    write `CONTAINS(STR(?s), "x")`. `CONCAT("a", 1)` is an error; write `CONCAT("a", STR(1))`.
  - The hash functions (§17.4.6), BNODE's label, REGEX's pattern and flags, and REPLACE's replacement take a simple
    literal or `xsd:string`.
- **`text:match` still reads IRIs.** It is Mercury's own function (ADR-051, Lucy's recall), not one of SPARQL's.
- **CONTAINS, STRSTARTS and STRENDS check argument compatibility,** as STRBEFORE and STRAFTER did (§17.4.3.9–11). A
  language-tagged second argument must have the first's tag.
- **REGEX's flags are XPath's** (`fn:matches`):
  - `q` makes every character of the pattern literal, so `REGEX(?o, "a.c", "q")` matches only `a.c`. With `q`, `m`,
    `s` and `x` have no effect, and `i` still does.
  - With `q`, REPLACE's replacement is literal too, so `$0` is text.
  - A flag other than `i`, `s`, `m`, `x` or `q` is an error (FORX0001). It was ignored.
- **The date functions take an `xsd:dateTime`** (§17.4.5, unchanged in SPARQL 1.2): YEAR, MONTH, DAY, HOURS,
  MINUTES, SECONDS, TIMEZONE and TZ.
  - A string, an IRI, an `xsd:date` or an ill-typed dateTime is a type error.
  - They read the fields as written, with no timezone conversion.
- **`24:00:00` is the next day's `00:00:00`** (XML Schema 2 §3.2.7). `HOURS("2020-02-29T24:00:00"^^xsd:dateTime)` is
  0, and DAY is 1 (March 1). Before, HOURS gave 24. Comparisons are unchanged: the instant was already right.

## Fixed

- **One test of a string literal,** `Value.IsStringLiteral`, for every string function. `Value.HasText` now serves
  only `text:match` and `IRI()`. Its doc comment had credited the IRI behavior to ADR-051, which covers `text:match`
  only.
- **One regular-expression builder,** `RegexOf`, for REGEX and REPLACE, with XPath's flags.
- **One reader of a dateTime or date lexical form,** `XsdDateTime.TryRead`. It returns the fields, validated, and
  `TryParse` computes the instant from them. The date functions' own loose reader (`TryParseDateTime`,
  `ExtractTimezone`) is deleted. It would read month 13, or a timezone from any six trailing characters.
- W3C dawg-regex-003, regex-no-metacharacters and regex-no-metacharacters-case-insensitive now pass.

## Tests and conformance

- New tests:
  - `StringFunctionArgumentTests` (17)
  - `DateFunctionArgumentTests` (13)
- **Existing tests rewritten to the spec forms:**
  - Six `FilterEvaluatorTests` applied a string function to `NOW()`, a STRDT result or a number. They now read it
    through `STR()`, and CONCAT of a number is asserted to be an error.
  - Seventeen bound a bare dateTime lexical form, which is a string. They now bind an `xsd:dateTime` term, as a scan
    does.
- **8 W3C known failures remain**, each with its cause in `W3CTestContext.KnownFailures`:
  - ADR-053 term identity (3);
  - malformed expressions accepted, which ADR-057 covers (3);
  - XMLLiteral exclusive canonicalization (2).
- Full suite: 6,199 tests, 0 failed, 17 skipped.

## Known, not changed

- **`text:match` misses an IRI that is a pattern's object.** The ADR-024 trigram pre-filter narrows a scan's object
  to atoms in the trigram index, and IRIs are not indexed until ADR-051. It does match IRIs bound by VALUES, and
  IRIs in a subject position. This was the same in 1.8.31.
