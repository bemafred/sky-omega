# Sky Omega 1.8.44 — Mercury: the store keeps when it memorized and when it forgot, and Cognitive SPARQL asks about both. DrHook: a stop detaches first; a Windows launch attaches in time

**Released:** 2026-11-20
**Version bump:** `Directory.Build.props` → 1.8.44 (with these notes)
**Predecessor:** [Sky Omega 1.8.43](1.8.43.md) — DrHook: a view shows the target's state as it is now, to the end.
Mercury: a store has one clock; a write is decided once.

## Headline

**Mercury remembers when.** A Cognitive store keeps, for each period in which a quad is remembered, two times on its
own clock: when the quad was memorized and when it was forgotten. No writer states them. A delete forgets and keeps
the period it ends, so nothing the store once remembered is lost. Cognitive SPARQL asks about both times with three
words, `MEMORIZED`, `FORGOTTEN` and `INCLUDING FORGOTTEN`, and a standard SPARQL 1.1 query means what it meant.

This is the purpose [ADR-061](../adrs/mercury/ADR-061-a-facts-own-times.md) set for the times in the design
discussion of 2026-11-11: they are for recall, on the memory's own time axis. "What did we memorize last week", "what
have we let go of since November", "what did we remember when we decided this": each is one query. When something
happened in the world is content, a triple with its source. The documents called the Cognitive profile bitemporal;
they now say memory time, one axis with two points per period.

The release also carries [ADR-062](../adrs/mercury/ADR-062-what-a-read-yields.md) (one cursor behind every read, and
result types that carry times only where a store keeps them), [ADR-063](../adrs/mercury/ADR-063-an-index-file-grows-by-extents.md)
(an index file that outgrew its first size crashed the process), and
[ADR-064](../adrs/mercury/ADR-064-a-facts-states.md) (the Graph and Minimal profiles number each fact's states and
keep no time).

**DrHook:** `drhook_stop` detaches before it ends a launched target, which removes the hang behind the macOS CI
failures (finding 110), and on Windows a launch attaches while the runtime is still held (finding 111).

## Mercury: Cognitive SPARQL

```
MEMORIZED [?t] [SINCE a] [BEFORE b]      after a triple pattern
FORGOTTEN [?t] [SINCE a] [BEFORE b]      after a triple pattern
INCLUDING FORGOTTEN                      after the query
```

```sparql
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>

SELECT ?g ?s ?label ?when WHERE {
  GRAPH ?g { ?s rdfs:label ?label MEMORIZED ?when SINCE NOW() - "P7D"^^xsd:dayTimeDuration . }
} ORDER BY DESC(?when)
```

- `MEMORIZED ?t` binds when the matched memory was memorized; `FORGOTTEN ?t` when it was forgotten, unbound while it
  is remembered. `SINCE` and `BEFORE` select by that time, alone, together or in either order; every range is
  half-open, `[a, b)`.
- The words apply to the one pattern they follow, so each pattern of a join keeps its own times. A pattern with
  `FORGOTTEN` matches forgotten memories too; `INCLUDING FORGOTTEN` makes every pattern of the query do so, a
  subquery's and a property path's included.
- A bound is a literal or an expression without variables, evaluated once per query: `NOW() - "P7D"^^xsd:dayTimeDuration`.
  A date is its first instant; a time without a timezone is UTC.
- A query without the words sees what is remembered now, and reads no clock (D7).
- Under `INCLUDING FORGOTTEN`, and in a pattern with `FORGOTTEN`, a graph variable ranges over every graph that holds a
  period. Forgetting the last fact of a graph no longer hides the graph's history (P3). On the live memory store eight
  graphs, 51 entries, were hidden this way.
- The words work in an Update's `WHERE`.
- **Errors:** a word after a property-path operator or inside `SERVICE`, a word or bound twice, a bound with a
  variable, `INCLUDING FORGOTTEN` on a subquery, and any word on a Graph, Reference or Minimal store, which keeps no
  times. Each is refused before anything is read.
- What was remembered at a time `t` has no word: it is two patterns in a `UNION`, with `b` one millisecond after `t`
  (Q10). See the [SPARQL reference](../architecture/technical/sparql-reference.md#memory-time-cognitive-sparql-adr-061).

## Mercury: what changes for a user of 1.8.43

**SPARQL.** `AS OF`, `DURING` and `ALL VERSIONS` are gone (D8); each is a syntax error. `ALL VERSIONS` becomes
`INCLUDING FORGOTTEN`. `AS OF t` becomes the two patterns of Q10. `DURING` selected by overlap with a range, which no
recall question asks; what it answered, the words answer.

**The store API** ([ADR-062](../adrs/mercury/ADR-062-what-a-read-yields.md) D6, ADR-061 Step 6):

| Before | Now |
|--------|-----|
| `Add`, `AddBatched` with stated times | gone: no writer states a time. `AddCurrent`, `AddCurrentBatched` read the store's clock |
| `Retract`, `RetractBatched` | gone: a fact recorded in error is forgotten like any other (D2) |
| `QueryCurrent` → `TemporalResultEnumerator` of `ResolvedTemporalQuad`, with made-up times on three profiles | `QueryCurrent` → `ResultEnumerator` of `ResolvedQuad`: the quad, on every profile |
| `QueryAsOf`, `TimeTravelTo`, `QueryChanges`, `QueryEvolution`, `Query(TemporalQueryType…)` | `QueryMemories`, Cognitive only, with the bounds of the words: `TemporalResultEnumerator` of `ResolvedTemporalQuad` |
| `ResolvedTemporalQuad` with `ValidFrom`-era legacy members and `RetractedAt` | the quad, `MemorizedAt`, and `ForgottenAt`, null while the memory is remembered |
| `TemporalQueryType`, `HistoryMode` | gone |

Mercury has 30 public types. `QueryMemories` on a store that keeps no times throws `ProfileCapabilityException`.

**Pruning** (D12). There is one way to prune: what is remembered is copied, each memory with the time it was
memorized, and nothing forgotten. A `FORGOTTEN` question on the pruned store finds nothing, and a store in which
everything is forgotten prunes to an empty store. The three history modes are gone; `PruneOptions.HistoryMode` and
`TransferOptions.HistoryMode` with them. The CLI refuses `--history` and says why: ignoring it would prune away the
forgotten memories its user asked to keep. Whoever wants every period kept copies the store.

**Graph and Minimal stores** (ADR-064). A Graph entry is the quad, the child pointer and the fact's version, 44
bytes, where it was 64; a Graph store has no TGSP. A Minimal store takes session writes with a log, soft deletes and
versions, as Graph does. **A Graph or Minimal store in the earlier layout is refused at open, and no store is
converted:** reload it from its source. A Reference store that holds its load refuses a second bulk load and
`BeginBatch` (D10).

**A Cognitive store that cannot apply a committed write stops** (P2): `CommittedWriteNotAppliedException` from that
write and from every later read, write and checkpoint; the store closes without a checkpoint, and opening it again
applies the log.

**A Cognitive index rebuild compares first** (`c3b6025`): if GPOS, GOSP or TGSP holds an entry GSPO does not hold as
it is, `RebuildSecondaryIndexes` changes nothing, logs a warning and throws, naming the counts. Otherwise it carries
every entry of every graph as it is. Before, it read only the default graph, kept what the targets already held, and
could write a retracted entry as remembered.

## Mercury: the rest of this release

- **`mercury.log`.** `mercury` and `mercury-mcp` keep a log beside the stores in the pool's directory: each run's start
  and stop, each store opened, each replay of a log, and every warning and error a store reported, with the stack of
  an internal error. Bounded at 4 MB, with one older file (ADR-061 M7).
- **An index file grows by extents** (ADR-063). A file that outgrew its first size was lengthened but not mapped
  again, and the next page access died with `AccessViolationException`: a Cognitive store with 1 MB index files died
  after 5,000 quads. A page cache without a lock gave readers each other's pages. The file is now mapped in extents
  that never move, and the page cache is gone.
- **One cursor** (ADR-062 part one). Every read of an index goes through one cursor; the four enumerators, their three
  flags and four of five constructors are gone.
- **The documents** say memory time in place of "bitemporal" wherever they describe Mercury as it is. Both
  `temporal-rdf.md` are rewritten, and the SPARQL reference has the words' rules. The `lucy` skill's recency recall
  orders by `MEMORIZED`, and `MERCURY.md` tells an agent to write no time of its own: the store keeps it. Two documents
  described an MCP tool `mercury_prune`, and two a `mercury prune` command; neither exists, and pruning is `:prune` in
  the CLI.
- **The MCP tool descriptions** name the words, and say that a write needs no timestamp.

## DrHook

- **`drhook_stop` detaches before it asks a launched target to exit** (finding 110). It resumed the target with every
  breakpoint active and then sent SIGTERM; a target that passed a breakpoint while it died left mscordbi's event
  thread waiting on the dead target with the DAC lock held, and every later attach and launch in the process hung:
  finding 100's cascade, the macOS CI failure. On macbook under load the integration suite hung in 15 of 40 runs with
  the old order; with the new one, 0 of 100 against 24 of 100.
- **On Windows a launch attaches while dbgshim holds the runtime** (finding 111). Main could start before DrHook
  attached, and a breakpoint set at the entry module missed the calls already made: the Windows `CaptureState`
  failure in CI. On omega-windows, through `drhook-mcp`, 30 launches with none late.
- `drhook_stop` and `drhook_kill` say what they do on each platform: on Windows there is no exit request, so a stopped
  target is killed after the detach.
- **The dashboard on a narrow terminal** keeps a frame's method and line, wraps the braid's lines, removes terminal
  escape sequences from the console pane and puts a breakpoint's hit count first. `drhook-viz-console` prints console
  output one line per line, each led by its stream: known in 1.8.43, fixed.
- **ADR-016:** finding 106 (the debugger in a worker process, measured on four machines: 104 of 104 recoveries on
  Linux and macOS) and finding 112 (cancellation under the debugger, on Linux, macOS and Windows) are recorded for
  Steps 3 and 5. Finding 103 was not reproduced in 200 runs on macbook.
- A test machine gets commits, never patches: the runbook says how.

## Opening a live store with 1.8.44, and going back

- **The Cognitive layout is unchanged** (ADR-061 D13). 1.8.44 opens a Cognitive store written by 1.8.41 to 1.8.43 as
  it is, and replays its log as written, its `Add`, `End` and `Retract` records included. An entry an older Mercury
  retracted stays retracted.
- **On omega this release ran on a copy of the live memory store before it was installed** (see Tests), and a
  byte-identical copy of the store from before the install is kept.
- **Going back:** a Cognitive write puts log records 6 to 9 in `wal.log`, which builds before 1.8.43 do not know and
  refuse to open (ADR-054 D8). After a clean close the log holds only its checkpoint record. This is read from the
  code; going back was not run.

## Known, not fixed

- **The selection query of a prune** waits for Martin's decision on its form (ADR-061 P4); today's graph and predicate
  filters are the selection. A prune does not yet report a disagreement between the source's indexes (I19).
- **The live memory store's indexes disagree** (ADR-061 LQ5): TGSP holds 204 entries open that GSPO holds forgotten,
  and 47 that only it holds. GPOS and GOSP equal GSPO. The words read GSPO, GPOS or GOSP, never TGSP. A rebuild refuses on such a store,
  and nobody rebuilds or prunes the live store until the rule for each difference is decided. Dogfooding the words on
  it with the checks of ADR-061 P9 waits for that.
- The Cognitive entry still holds its five `Legacy` fields; they leave with the stored-layout change (ADR-061, the
  later part).
- Disposing a store while a batch holds the write lock throws `SynchronizationLockException` over the exception that
  ended the batch. A store refused at open leaves open the files it opened before the refusal.
- **An installed `mercury-mcp` before 1.8.44 does not know the words.** The `lucy` skill uses them; with an older
  server its temporal modes are a syntax error, which the skill names. On zbook the Mercury tools stay at 1.8.42 until
  1.8.44 has run on a copy of that machine's memory store.
- A target that dies during a mscordbi request still leaves the DrHook debugger unusable in its process until the MCP
  server restarts (finding 105). The worker process (ADR-016 Step 5) is measured, not built.
- A DrHook target that exits while no tool call waits for it is shown as `Running` until the next tool call.
