# Sky Omega 1.8.37 — Mercury: one N-Triples and N-Quads parser and writer; N-Triples reads UTF-8; convert writes every format

**Released:** 2026-10-30
**Version bump:** `Directory.Build.props` → 1.8.37 (with these notes)
**Predecessor:** [Sky Omega 1.8.36](1.8.36.md) — Mercury: RDF/XML namespaces by Namespaces in XML.

## Headline

**The N-Triples parser read UTF-8 as Latin-1,** one character per byte, so every non-ASCII literal or IRI loaded from
N-Triples was stored wrong: `café` as `cafÃ©`. The RDF 1.2 canonical-form tests found it, and with it two more bugs in
the N-Triples and N-Quads code.

N-Triples and N-Quads each had their own parser and their own writer. Each copy had bugs the other did not. N-Triples
is N-Quads without graph labels, so each pair is now one implementation:

- `NQuadsStreamParser` is the one parser. `NTriplesStreamParser` reads through it and rejects a graph label.
- `NQuadsStreamWriter` is the one writer, writing canonical form. `NTriplesStreamWriter` writes through it.

**`mercury --convert` wrote nothing for any output format except N-Triples.** `mercury --convert in.nt out.nq`
printed "Converted 1 triples." and left an empty file. It now writes every format and keeps each statement's graph.

**Sky Omega has continuous integration:** GitHub Actions builds and tests every push on six platforms, Windows x64 and
macOS x64 among them. Neither had been run before.

## Changed: what parsing returns

Each change follows the N-Triples and N-Quads grammars. Each was wrong before, in one parser or both.

- **N-Triples decodes UTF-8.** Invalid UTF-8 is now a parse error in both formats. A character split across the
  buffer boundary is decoded whole; N-Quads used to decode it as garbage.
- **A long literal parses in N-Quads.** The N-Quads parser did not refill its buffer in the middle of a statement, so
  a literal longer than about 6 KB was "Unterminated". N-Triples got this fix in 1.7.4; N-Quads never did.
- **Whitespace may separate a literal from its language tag or `^^`, and `^^` from the datatype.** They are separate
  terminals in both grammars. Both parsers rejected the whitespace.
- **One statement per line in N-Quads.** The N-Quads parser accepted a second statement after the `.` on the same line.
- **Blank node labels are read by code point.** The copies cast each code point to `char`, which dropped U+10000 to
  U+EFFFF, and they accepted any Unicode digit. Labels now follow the grammars' `PN_CHARS_BASE`, `PN_CHARS_U` and
  `PN_CHARS`, held once in `RdfNameChars`.

**Documents that loaded before may now fail to load:** an N-Triples or N-Quads file with invalid UTF-8, or an N-Quads
file with two statements on one line. Before, the first loaded with wrong text and the second loaded without an error.

**Data loaded from N-Triples before 1.8.37 holds wrong text** wherever the source had non-ASCII characters. Load it
again to correct it.

## Changed: what writing produces

N-Triples and N-Quads output is canonical (RDF 1.2 N-Triples, Canonical N-Triples):

- **`"` and `\` are escaped in N-Quads.** The N-Quads writer found a literal's closing quote by scanning forward, which
  cannot work on the decoded form the parsers store, so it wrote `"x"y"` and left `\` bare. That output was not
  N-Quads.
- **Control characters:** backspace, tab, line feed, form feed, carriage return, `"` and `\` as `\b \t \n \f \r \" \\`.
  U+0000 to U+0007, vertical tab, U+000E to U+001F, DEL, U+FFFE, U+FFFF and lone surrogates as `\uXXXX` with uppercase
  hex. Before, backspace and form feed were `\u0008` and `\u000C`.
- **Every other character is written as itself.** Before, all non-ASCII was `\uXXXX` or `\UXXXXXXXX`.
- **A language tag is written in lowercase, and an `xsd:string` literal without its datatype.** This is output only.
  How terms are stored and compared is [ADR-053](../adrs/mercury/ADR-053-one-rdf-term-one-atom.md)'s.

**RDF/XML output declares every prefix it uses.** The writer made up a prefix for a predicate's namespace after it had
written `rdf:RDF`, and used it without declaring it: `<ns3:p>` with no `xmlns:ns3`. That is not well formed under
Namespaces in XML, and Mercury's own parser rejects it since 1.8.36. It affected all RDF/XML output, SPARQL
CONSTRUCT results included. A prefix the root does not declare is now declared on each property element that uses it.

## Fixed

- **`ConvertAsync` writes every format.** For every format but N-Triples, its switch fell through to a write that did
  not exist. It also parsed through the triple-only `ParseAsync`, so the graphs of N-Quads, TriG and JSON-LD input were
  lost. It now reads through `ParseQuadsAsync`.
  - A named graph written to N-Triples, Turtle or RDF/XML is a `NotSupportedException` that names the graph. It is
    not dropped, and not merged into the default graph.
- **One map from an RDF format to its writer,** `RdfDocumentWriter`. It is used by `ConvertAsync`, `WriteTriples`,
  `WriteQuads` and the Turtle tool's convert. The Turtle tool had its own copy of the switch, without RDF/XML or
  JSON-LD. Disposing it completes the document once.
- **`WriteQuads` writes one JSON-LD document.** It flushed the JSON-LD writer and then disposed it, and both wrote the
  whole document.
- **The parallel bzip2 stream rejects concatenated input.** Given `cat a.bz2 b.bz2`, `ParallelBZip2DecompressorStream`
  returned the first stream's bytes alone and reported success. It now throws `InvalidDataException` when another
  stream follows the first. `BZip2DecompressorStream` reads concatenated streams, as before.
- **`tools/update-submodules.ps1` lists the submodule paths under Windows PowerShell 5.1.** 5.1 broke the quotes nested
  in the argument to git; PowerShell 7 was not affected.

## Every W3C test runs: phase 1

About 1,400 W3C tests in the two test-data submodules were in no manifest the suite loaded, so they neither failed nor
counted. [ADR-059](../adrs/mercury/ADR-059-every-w3c-test-runs.md) (Proposed) makes every manifest load, and lists
every test that cannot pass yet as a known failure by its exact test IRI.

Phase 1 is in this release:

- **The Turtle, TriG, N-Triples, N-Quads and RDF/XML suites load the RDF 1.2 manifests.** These include the RDF 1.1
  ones, so each test runs once. The test methods are named for the format (`Turtle_Eval`, not `Turtle11_Eval`).
- **The canonical N-Triples and N-Quads tests run,** as a new test kind, `CanonicalForm`: the input is parsed and
  written back by Mercury's writer, and must equal the expected file.

The format suites run 1,334 tests: 1,180 pass and 154 are known failures, all RDF 1.2 features that Mercury does not
read yet:

- triple terms `<<( s p o )>>`, outside Turtle;
- reified triples and reifiers `<< s p o ~ r >>`;
- annotations `{| … |}`;
- base direction `"x"@en--ltr`;
- `VERSION`;
- RDF/XML's `rdf:annotation`, `rdf:dir` and triple terms.

Every RDF 1.1 test still passes. `W3C_RUN_KNOWN_FAILURES=1` runs the known failures.

## Tests and conformance

- **30 new tests,** inline:
  - parsing: non-ASCII decoded; a four-byte character at every alignment across a 16-byte buffer; invalid UTF-8
    rejected; a graph label in N-Triples rejected; whitespace before `@` and `^^`; a 20,000-character N-Quads literal
    through a 16-byte buffer; a supplementary-plane blank node label; two statements on one line rejected;
  - writing: the decoded quote and backslash in N-Quads; canonical control characters; language-tag and `xsd:string`
    canonical form;
  - convert: N-Triples to N-Quads keeps every statement; a named graph is kept in TriG and refused in N-Triples; Turtle
    to RDF/XML and to JSON-LD round-trips; `WriteQuads` writes one JSON-LD document; the RDF/XML writer declares a
    prefix it makes up;
  - bzip2: an empty stream; concatenated streams, read in order or rejected; truncation at five points in both streams;
    no allocation after the first read.
- **Two writer tests changed their expectation** to canonical form: an emoji is written as itself, not `\U0001F600`; a
  datatyped-literal test now uses a datatype other than `xsd:string`, so it still tests a datatyped literal.
- **W3C:** 341 more tests run, the RDF 1.2 and canonical-form tests. Known failures: 160, of which 154 are RDF 1.2 and
  6 are SPARQL 1.0 as at 1.8.36; 6 JSON-LD tests do not apply, as before.
