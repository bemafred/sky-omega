# Sky Omega 1.8.30 — Mercury: MIN and MAX order as ORDER BY does

**Released:** 2026-10-28
**Version bump:** `Directory.Build.props` → 1.8.30 (with these notes)
**Predecessor:** [Sky Omega 1.8.29](1.8.29.md) — Mercury: the SPARQL 1.0 suite runs, and an expression value is the
RDF term.

## Headline

**MIN and MAX take any term, not only numbers.**
- They read their argument as a number. Any other value, a date included, made the aggregate an error, so
  `MIN(?date)` and `MAX(?date)` returned nothing.
- SPARQL defines them by ORDER BY's order (§18.5.1.4–5). They now compare with the comparer ORDER BY uses, and return
  the winning term as stored: `MAX` of `"02"^^xsd:integer` and `"10"^^xsd:integer` is `"10"^^xsd:integer`, and
  `MIN` of `"02"` and `"10"` keeps `"02"`.
- Over mixed kinds the order is ORDER BY's: blank nodes, then IRIs, then literals; among literals, numbers, booleans,
  strings, tagged strings, then other datatypes.

**Found by the ADR-056 dogfood.** A memory recall through the MCP at 1.8.29 grouped stored `xsd:date` values by
predicate, and its `MIN` and `MAX` columns were empty. The same run passed the dogfood's two checks:
- `FILTER(?d >= "2026-06-01"^^xsd:date)` with `ORDER BY DESC(?d)` returned the stored dates by value;
- `FILTER(isNumeric(?o) && ?o > 1000)` matched stored `xsd:long` and `xsd:decimal` values, including the earlier
  writers' `^^xsd:long` form.

[ADR-056](../adrs/mercury/ADR-056-expression-value-is-the-term.md) is **Completed**.
