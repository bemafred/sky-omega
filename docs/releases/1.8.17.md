# Sky Omega 1.8.17 — Mercury's store pool reports its state; first Linux arm64 run

**Released:** 2026-10-26
**Version bump:** `Directory.Build.props` → 1.8.17 (with these notes)
**Predecessor:** [Sky Omega 1.8.16](1.8.16.md) — DrHook: VSTest tests sync on the target, not the clock.

## Headline

On omega-ubuntu, a Parallels VM running Ubuntu 26.04.1 on Linux arm64 (4 cores, 8 GB), `dotnet test` never finished:
Mercury.Tests hung at its 138th test. It was a Mercury bug. The test store pool sized itself from the free space on
`/` (46 GB) instead of the RAM-backed `/tmp` where its stores live (3.7 GB), came out at 2 stores for a test that
needed 3, and the third `Rent()` waited forever with no sign of why.

The pool now reports its state instead: its capacity decision when it is created, and each `Rent()` that has to wait
and when that wait ends. Free space is measured on the filesystem that actually holds the path.

It was also the first DrHook run on Linux arm64: 16 of 17 integration tests passed at once, and the 17th is fixed
here ([finding 95](../../poc/drhook-engine/findings/95-flood-test-target-exits-before-dispose.md)).

## Added

- **Store pool events** on `IObservabilityListener`:
  - `OnStorePoolCapacity`: the capacity decision at pool creation, with every input (requested concurrency,
    free space, budget fraction, per-store estimate) and which one bounded it.
  - `OnStorePoolRentBlocked` / `OnStorePoolRentResumed`: a `Rent()` found every store leased and waited, and when it
    got one. A blocked event with no resumed event is a lease waiting on a store nobody returned.
  - `JsonlMetricsListener` writes them as `store_pool_capacity`, `store_pool_rent_blocked` and
    `store_pool_rent_resumed` records.
  - Pass a listener to the temporary-pool constructor or set `QuadStorePoolOptions.ObservabilityListener`.
- **`DiskSpaceGuard.FileSystemOf(path)`**: the filesystem that holds a path, even one not created yet.

## Fixed

- **Free space was measured on `/`, not on the path's filesystem** (Linux and macOS). `Path.GetPathRoot` is always
  `/` on Unix, so a tmpfs `/tmp` or a separate data disk was invisible. One function now does the measurement, and the
  store pool, `QuadStore`'s low-disk check, the disk-free metric and the `mercury` CLI's free-space lines all use it.
  The duplicate in `StorageOptions.cs` is gone.
- **The pool's store-size estimate ignored `ForceAtomHashCapacity`.** It applied the 8 GB bulk-mode hash-table floor
  even when the store would not, so pools for `--atom-hash` bulk loads were over-estimated by 8 GB.
- **`Rent()` waiting forever with no trace.** It still waits without a timeout, since a wait is a state change and
  not an error, but the wait is now reported (above).
- **Two DrHook flood tests disposed on the clock, not during the flood.** On Linux arm64 the target finished and
  exited inside the test's wait. Both now dispose on the target's first thread callback inside its work loop
  ([finding 95](../../poc/drhook-engine/findings/95-flood-test-target-exits-before-dispose.md)).

## Changed

- **The test host observes the pool like any host.** `DiagnosticMessageListener` sends the pool events to xunit
  diagnostic messages, now enabled in `tests/Mercury.Tests/xunit.runner.json`. The pool tests use test-sized stores,
  check the pool's capacity before relying on it, and follow the blocked/resumed events instead of sleeping.

## Validation

- **omega-ubuntu (Linux arm64):** full `dotnet test` with nothing excluded: Mercury.Tests 4,724 passed, 0 failed,
  6 skipped (was a hang); DrHook integration 17/17 in three runs.
- **omega (macOS, M5):** Mercury.Tests 4,724 passed, 0 failed, 6 skipped; DrHook integration 17/17 in three runs.
- **elite and zbook (Linux x64):** DrHook integration 17/17, twice each.

## Known issues

- **`dotnet test` does not show xunit's diagnostic messages**, so the pool events (and xunit's long-running-test
  notices) print live only when the test executable runs under xunit's own runner
  (`tests/Mercury.Tests/bin/<config>/net10.0/Mercury.Tests`). That runner also now prints about a dozen existing
  "non-serializable data" warnings at discovery.
- **`dotnet test` exits 0 when its front end gets SIGTERM**, with no summary (Microsoft.Testing.Platform, SDK
  10.0.301 and 10.0.113). Killing the test process itself, or Ctrl+C, reports failure correctly. Upstream behaviour,
  not yet reported.
- Carried over: NCrunch is unverified with xunit.v3.
