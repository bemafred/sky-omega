# Sky Omega 1.8.28 — Mercury: DESCRIBE reads every graph

**Released:** 2026-10-28
**Version bump:** `Directory.Build.props` → 1.8.28 (with these notes)
**Predecessor:** [Sky Omega 1.8.27](1.8.27.md) — Mercury: DESCRIBE, SELECT *, $x and blank nodes follow the spec.

## Headline

After 1.8.27, a live check on the MCP memory store found that `DESCRIBE <iri>` returned nothing. DESCRIBE read only
the default graph, and the memory store keeps every triple in a named graph. SPARQL 1.1 §16.4 leaves the description
to the service. Mercury now describes from every graph, as of the query's time.

## Fixed

- **DESCRIBE read only the default graph.** It now reads the default graph and every named graph, and returns a
  triple stored in several graphs once. With FROM or FROM NAMED, it reads only the graphs they name.
- **DESCRIBE ignored the temporal clause.** `AS OF`, `DURING` and `ALL VERSIONS` now apply, so
  `DESCRIBE <iri> AS OF "2021-06-15"^^xsd:date` returns the triples valid then.
- **The DESCRIBE target list ended at any token starting with a keyword**, a bug introduced in 1.8.27:
  - `DESCRIBE orders:x`, `values:y` or `from:z` found no target;
  - `AS` in `AS OF` was read as a target.

  A target is now recognized by its form: a variable, a `<…>` IRI, or a token with a colon.

## Changed

- `TemporalScope` reads the store through a query's temporal clause. The triple scan and DESCRIBE both use it, so the
  scan's own copy of that choice is gone.
- Stack use is unchanged: 23–39 KB across the probe shapes (`tools/probes/stack`).

## Validation

- `DescribeTests` has 5 new cases (17 in all): named graphs, a triple in two graphs, FROM, AS OF, and a prefix that
  starts like a keyword. Each new case failed before the fix.
- Mercury.Tests: 4,891 passed, 0 failed, 7 skipped, W3C SPARQL 1.1 conformance included. Mercury.Solid.Tests: 25/25.

## Known issues

- Carried over from [1.8.27](1.8.27.md#known-issues):
  - a blank-node label is one variable across the whole query;
  - a VALUES number comes back typed while a BIND number comes back bare (ADR-053);
  - HAVING matches aggregates by their text;
  - the SPARQL 1.0 W3C manifests are not run;
  - DISTINCT compares rows by a 32-bit hash;
  - on Linux, one debugger thread leaks per ended DrHook session;
  - Windows lacks `RequestExit`.
