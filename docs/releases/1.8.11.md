# Sky Omega 1.8.11 — DrHook: the braid, cooperation-free visual capture, and the production pass

**Released:** 2026-10-24
**Version bump:** `Directory.Build.props` → 1.8.11 (`4984c89`)
**Predecessor:** [Sky Omega 1.8.10](1.8.10.md) — DrHook source-on-step views + typed value rendering.

## Headline

1.8.11 collects four months of DrHook work in one release: 36 commits from 2026-06-27 to 2026-10-24.

The June work makes the agent's debugging visible. The `(hypothesis, observation)` braid now shows in the live view and is saved to Mercury. The agent can see the debug state as an image. And DrHook can capture the pixels of a GUI app's window without changing that app at all.

In October, after a three-month pause, we took the visibility tools to production. Using them on today's OS (macOS 27, M5) surfaced five defects. Each was already in the code, and a passing test suite had hidden every one of them. All five are fixed. The release ends with the full-screen TUI dashboard and docs that give the store path for every platform, written for the new Linux rig.

## The braid becomes visible and durable (ADR-012 Phase 3)

- **Hypothesis as a delta** (`11c27d9`). The hypothesis the operator states is now a `DebugStateDelta` kind, emitted at the MCP boundary for navigation (continue/step/pause) and inspection (locals/expand). The live view shows it on the line before the observation it predicts: `▸ <lens>: <text>`. Before that, a legibility probe validated the record shape (`37ee0bb`).
- **`DrHook.Capture`** (`844ea96`) is the durable consumer of the same stream. A standalone transport client writes it as raw, append-only triples to a dedicated Graph-profile Mercury store, one named graph per session, so Lucy can recall it later. It references `DrHook.Viz` and Mercury, not `DrHook.Engine`, so the engine stays substrate-independent. Its default store path now comes from `MercuryPaths.Store("drhook")` (`efbdd23`), so it is correct on every platform.

## Seeing state as an image (ADR-012)

- **`drhook_snapshot_image`** (`1dda929`, `8cd1273`) renders the current debug state as a PNG: session, stop, call stack, source pane, locals, breakpoints. It returns the image as MCP image content. It is all BCL: a hand-written grayscale PNG writer, an embedded public-domain 8×8 bitmap font, and the same `DebugStateTextRenderer` the console view uses. The image therefore shows exactly what a view shows; there is no second renderer to drift. With `drhook_capture_visual` (below), the MCP surface grows from 23 to 25 tools in this release. The commit message for `8cd1273` says "22 → 23", but the code at `fc6cecc` already had 23.

## Capturing a GUI app's own pixels, without its cooperation (ADR-012 Q8 a)

A target should be visually debuggable as it is, with no capture hook built in. Seven func-eval primitives make that possible:
1. Chaining results (`2724b7a`).
2. Chaining getters (`53bc1b9`).
3. N-argument instance calls (`78099f3`).
4. `NewObject` (`33f5fa1`).
5. `NewString` (`1e927ec`).
6. Value-type construction (`54cf95a`).
7. Render-capture orchestration (`15fd68a`). It walks to the live top-level visual, builds a render-target bitmap, renders into it, and saves it, all by func-evaluating the debuggee's own APIs.

**`drhook_capture_visual`** (`5001451`) makes this an MCP tool. Its defaults suit Avalonia, but the recipe is not tied to a framework. Attach also gained a Pause fallback: an idle GUI app blocked in its native message pump never reaches a managed safe point on its own, so attaching to one used to time out. A `stopAfter` checkpoint knob (`94af545`) bisects the capture chain. With it we showed that no single step reliably hangs the target: 40 clean captures against one original hang.

## Other June work

- **ADR-013 Completed** (`d849fb6`). A condition or logpoint can read `Span<T>.Length` straight from the `_length` field, since a ref struct cannot be func-eval'd. This was validated live at a real `BindingTable.Bind` frame.
- **Source breakpoints are registered through one path** (`adc54b4`). A breakpoint set at launch or attach could be listed but not removed by id, because registration had three copies and one of them was incomplete. All three now go through `TrackSourceBreakpoint`.
- **ADR status audit** (`95aee0e`). ADR-006 and ADR-011 are now Completed, and ADR-005 is Superseded by ADR-006.
- **ADR-015 run-until-anomaly** (`2ab2212`, Proposed). It proposes repeat-until-failure as a first-class DrHook tool that freezes the target at the failure, instead of only reporting it.

## Mercury fix

- **`GetNamedGraphs` works on graph-aware profiles** (`269cc98`). Named-graph enumeration was hardcoded to the temporal index, so a Graph-profile store could not list its own graphs, and `GRAPH ?g` threw "requires temporal". `NamedGraphEnumerator` now handles both the temporal and the versioned index. `DrHook.Capture`'s Graph-profile store surfaced this.

## The October production pass

The goal was to bring the visibility tools to production on simple foundations: a reliable test baseline, a root cause or a guard for the `capture_visual` hang, and the read-only scope of ADR-012 closed.

| Finding | What broke | Fix |
|---------|------------|-----|
| 87 (`0d48a22`) | The BCL and the in-process debugger's PAL both reaped the same child process, which ended in a FailFast. | A `TargetIsHostChild` guard, plus a `/bin/sh` harness topology. |
| 88 (`3c7ddb5`) | dbgshim's `EnumerateCLRs` crashed the debugger on any Metal GUI app (macOS 27, M5 GPU metallib without `LC_SYMTAB`). | Attach locates `libcoreclr` itself through a region walk of the process's mapped files. An upstream issue is drafted (`poc/drhook-engine/findings/88-dbgshim-upstream-issue.md`). |
| 89 (`80568f8`) | An idle detach from an attached (Borrowed) process leaked the `CordbProcess`, and the host crashed when the target later exited. Probe 62 had fixed only the launched (Owned) copy of this code. | One `DetachSynchronized` sequence for both. |
| 90 (`63d14d8`) | Test hosts left waiting for a debugger leaked on every VSTest run: 346 of them, 17 GB. | Kill the run's process group. |
| 91 (`0a8dc29`) | With `VSTEST_HOST_DEBUG`, an early attach skipped the hold. | Force the stop with Pause. |

Also in October:
- **UI-liveness guard** (`f2ec221`). In 1 of 41 observed captures, the app's UI thread was left hung, and the root cause was never reproduced. After a capture, detach now queues a sentinel `File.Delete` on the UI dispatcher and reports `uiLiveness` as `alive`, `unresponsive` or `not-checked`. `unresponsive` raises `AnomalyKind.UiThreadUnresponsive`. A silent hang becomes a verdict.
- **Every breakpoint hit is counted** (`109e197`). A breakpoint with no policy never counted its hits, and exception filters had the same gap. Every hit is now counted in one place, before any policy runs.
- **`drhook-viz-tui`** (`6e57359`) is the full-screen dashboard, built for ADR-012 Phase 4. It shows title, stack and source; locals and breakpoints; braid and events; console and anomalies. It uses only BCL `System.Console` and ANSI, which resolves Q2. The console pane shows the target's captured stdout and stderr, which resolves Q5; hosting a real PTY is deferred. Text from the debuggee is sanitized, so an ESC from the target cannot reach your terminal.
- **The DRHOOK.md tool reference matches the 25-tool surface again** (`a1bf151`, `0f72eb1`), including the `capture_visual` hang caveat.
- **Store paths for every platform** (`ea3b45f`). Docs and help texts named only the macOS path. They now give macOS (`~/Library/SkyOmega/stores/`), Linux (`$XDG_DATA_HOME/SkyOmega/stores/`, by default `~/.local/share/...`) and Windows (`%LOCALAPPDATA%\SkyOmega\stores\`). We found this on the first run on a fresh Linux machine.

**Gates:** the DrHook integration suite passed 50/50 twice, and every integration test also passes when run alone.

## Still open

- ADR-012 stays Proposed. The command half of Q3 (Phase 5) and PTY hosting are not built.
- The `capture_visual` hang is guarded, but its root cause was never caught.
- The dbgshim upstream issue (finding 88) is drafted, not filed.
- The October pass was validated on macOS 27 / M5 only.
