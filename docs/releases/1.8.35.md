# Sky Omega 1.8.35 — Mercury: an XMLLiteral is its canonical form

**Released:** 2026-10-29
**Version bump:** `Directory.Build.props` → 1.8.35 (with these notes)
**Predecessor:** [Sky Omega 1.8.34](1.8.34.md) — Mercury: function arguments by the spec.

## Headline

**An RDF/XML `parseType="Literal"` is its exclusive canonical form** (xml-exc-c14n with comments, RDF/XML §7.2.17).
Before, Mercury:
- wrote every in-scope namespace on every element of the literal;
- dropped the default namespace;
- wrote an end tag as `<//b>`;
- copied text and references as they were written.

**Every W3C RDF format suite passes.** 2 known failures pass, so 6 remain (8 at 1.8.34), all in SPARQL 1.0:
- 3 wait on ADR-053 (term identity);
- 3 wait on ADR-057 (malformed expressions accepted).

## Changed: what parsing returns

These changes follow RDF/XML and Exclusive XML Canonicalization. Each was wrong before.

- **Namespaces:**
  - An element of the literal declares only the namespaces it visibly uses: its own prefix and its attributes' prefixes.
  - It declares one only if no element above it in the literal declared the same binding.
  - The default namespace is declared where it is used. `<br />` under a default xhtml namespace is
    `<br xmlns="http://www.w3.org/1999/xhtml"></br>`.
  - Declarations are sorted by prefix, with the default first. Unused declarations from `rdf:RDF` are left out.
- **Attributes** are sorted by namespace IRI, then local name. Unprefixed attributes come first.
- **An empty element is a start and an end tag:** `<eg:b/>` is `<eg:b></eg:b>`.
- **Text and attribute values are in canonical form:**
  - References are decoded, then escaped again.
  - In text: `&`, `<`, `>` and CR are escaped.
  - In attributes: `&`, `<`, `"`, tab, LF and CR are escaped.
  - So `&#62;` in text is `&gt;`, and `'x"y'` in an attribute is `"x&quot;y"`.
  - A CDATA section is its text, escaped. Comments and processing instructions are kept. Line ends are LF.
- **A self-closing `parseType="Literal"` is `""^^rdf:XMLLiteral`.** It was a plain literal.
- **A self-closing `parseType="Collection"` is `rdf:nil`** (§7.2.19).
- **Any `parseType` other than `Resource` and `Collection` is treated as `Literal`** (§7.2.20), with or without
  content.

**XML literals already stored keep the form they were stored with.** Loading the same document again stores the
canonical form as a separate term.

## Fixed

- **An end tag inside an XML literal** was written as `<//b>`. The `/` was not consumed.
- W3C xml-canon-test001 and xml-canon-test002 pass.
- **Three more W3C tests now give the expected result:** rdfms-xml-literal-namespaces-test001 and -test002, and
  rdfms-empty-property-elements-test003. The upstream manifest leaves these three out.
- **A test that could hang the suite.** The full suite hung once, for about two hours, in
  `OrderedParallelPipelinePoCTests`. That test's own copy of the parallel bzip2 orchestration decided it was done when
  the input channel's `Reader.Completion` was complete, but nothing signals the consumer after that is set:
  - `BoundedChannel.TryComplete` marks the writer done inside its lock and sets `Completion` after leaving it.
  - In that gap, the last worker can find no more input, signal and exit.
  - The consumer then sees `Completion` still incomplete and waits for good.

  The copy now ends on a producer-done flag that is set under its lock and then signalled.
  `ParallelBZip2DecompressorStream`, which the copy mirrors, already did this and is not affected.

  The cause was found in the .NET 10 channel source and the stacks of the hung run. A probe did not reproduce it in
  300,000 runs: the gap is a few instructions long.

## Known, not changed

- **RDF/XML namespace declarations are not scoped to their element.** The parser keeps one table of prefixes for the
  whole document. A declaration stays bound after its element ends, and a redeclaration replaces the outer binding
  for the rest of the document. So a prefix declared on one element still resolves on its later siblings, and a
  prefix redeclared inside one element keeps the inner namespace after that element ends. An XML literal keeps its
  own correct scope. No W3C test fails on this today.
- **DrHook cannot yet show where every thread of a hung process waits.** `drhook_snapshot` reports thread sample
  counts without frames, and `drhook_pause` reads the top frame of one thread. The hung test above was found with
  `dotnet-trace` instead.
