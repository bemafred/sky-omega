# Sky Omega 1.8.36 — Mercury: RDF/XML namespaces by Namespaces in XML

**Released:** 2026-10-29
**Version bump:** `Directory.Build.props` → 1.8.36 (with these notes)
**Predecessor:** [Sky Omega 1.8.35](1.8.35.md) — Mercury: an XMLLiteral is its canonical form.

## Headline

**The RDF/XML parser reads namespaces as Namespaces in XML defines them.** RDF/XML builds on that spec (RDF 1.1 XML
Syntax §6). Before, Mercury:
- kept one table of prefixes for the whole document, so a declaration stayed bound after its element ended;
- read an undeclared prefix as an empty namespace, so `eg:p` became the IRI `<p>`, with no error;
- bound `rdf` without a declaration;
- recognised RDF/XML's own attributes (`rdf:about`, `rdf:resource` …) by how they were written, not by their
  namespace.

No W3C test failed on any of these. Every W3C RDF/XML test document that uses `rdf:` declares it.

## Changed: what parsing returns

These changes follow Namespaces in XML and RDF/XML. Each was wrong before.

- **A namespace declaration ends with its element** (Namespaces in XML §6.1).
  - A prefix redeclared inside one element no longer keeps the inner namespace for the element's later siblings and
    the rest of the document. A default namespace (`xmlns="…"`) is no longer carried over either.
  - This covers node elements, property elements, `parseType="Resource"` content, collection items, and XML literals.
- **An undeclared prefix is a parse error** (constraint Prefix Declared). It used to give an IRI of the local name
  alone. This includes a prefix used after its declaration has ended, which used to resolve to the stale binding.
  - It applies in element names, attribute names, and inside an XML literal.
  - An unprefixed name with no default namespace is still in no namespace.
- **`xmlns:p=""` is a parse error** (Namespaces in XML 1.0 §3). Only the default namespace can be undeclared this way.
- **`rdf` must be declared.**
  - RDF 1.1 XML Syntax §2.6: "any XML namespaces must still be declared". §5.1: the RDF namespace "is typically
    used in XML with the prefix rdf although other prefix strings may be used".
  - Only `xml` (and `xmlns`) are bound without a declaration, as in XML.
  - Predeclared prefixes are a standard only in RDFa: its initial context predefines 46, including `rdf`, `rdfs`,
    `xsd` and `owl`, for RDFa documents.
- **RDF/XML's attributes are matched by namespace** (§5.1).
  - Under `xmlns:r` bound to the RDF namespace, `r:about`, `r:resource`, `r:parseType`, `r:datatype` and the others
    are read as RDF syntax. Before, they were read as property attributes.
  - Under `rdf` bound to another namespace, `rdf:about` is an ordinary property attribute. Before, it was read as the
    subject.
- **An attribute written twice under different prefixes for one namespace is a parse error** (Namespaces in XML
  §6.3), such as `rdf:about` and `r:about` on one element.
- **A property element's `rdf:value`, or any `rdf:` attribute other than the syntax attributes, makes its object a
  blank node.** `<eg:p rdf:value="x"/>` gave an empty literal; it now gives a blank node with `rdf:value "x"`.

**Documents that loaded before may now fail to load:** an RDF/XML file that uses `rdf:` or any other prefix without
declaring it is rejected. Before, it loaded silently with wrong IRIs.

## Fixed

- **One namespace scope.** Each declaration records the binding it replaced (`DeclareNamespace`), and an element's
  parser rolls back to where its start tag began when the element ends (`EndNamespaceScope`). The XML literal
  canonicalizer used to keep its own copy of the scope (a stack of dictionaries); it now uses the parser's, so one set
  of rules covers both.
- **One attribute reader.** `ParseAttributes` reads the whole start tag, then keys each attribute by namespace and
  local name, so a declaration written after the attribute that uses it still applies.
- **One test of a property attribute,** `PropertyAttributePredicate`. Two copies had drifted:
  - the check that decides whether a property element's object is a blank node skipped every `rdf:` attribute;
  - the code that writes the triples treated `rdf:value` and the others as properties.

  - `RdfXmlNamespaceScopeTests` (15): 7 on declaration scope, 8 on undeclared and empty prefixes.
  - `RdfXmlAttributeNamespaceTests` (7).
