# Sky Omega 1.8.38 — Mercury: written text has no byte order mark; the pruning audit log is N-Quads

**Released:** 2026-10-30
**Version bump:** `Directory.Build.props` → 1.8.38 (with these notes)
**Predecessor:** [Sky Omega 1.8.37](1.8.37.md) — Mercury: one N-Triples and N-Quads parser and writer; N-Triples
reads UTF-8; convert writes every format.

## Headline

**Eleven writers began their text with a UTF-8 byte order mark** (EF BB BF). Each passed `Encoding.UTF8` to
`StreamWriter`, whose preamble is the byte order mark. They now use the BCL default, UTF-8 with no byte order mark.

No test saw it: HttpClient's `ReadAsStringAsync` and `StreamReader` drop a byte order mark, so a test that reads text
never sees one. The new tests read bytes.

## Fixed: no byte order mark

- **SPARQL HTTP responses:** SELECT, ASK and CONSTRUCT bodies, JSON included. RFC 8259 §8.1 forbids a byte order mark
  in JSON sent over a network.
- **Solid GET bodies,** for resources and containers.
- **The JSONL metrics listener,** on a stream and in a new file. 15 of the 52 metrics records in `docs/validations/`
  start with one. Strict JSON readers reject such a record: Python's `json.loads` raises "Unexpected UTF-8 BOM". The
  committed records are left as they were recorded.
- **The attach pipe** (`mercury --attach`), server and client.
- **`mercury-turtle --output`.** The tool's own parser rejected the file it wrote: "Unexpected character U+FEFF".
- **The pruning audit log,** below.

## Fixed: the pruning audit log is N-Quads

`PruningTransfer` wrote its audit log of excluded quads by hand. It put angle brackets around terms that already have
them, and wrote literals as stored, with their escapes decoded. So this statement:

```
_:b1 <http://example.org/p> "line one\nline two" .
```

came out as:

```
<_:b1> <<http://example.org/p>> "line one
line two" .
```

The log was never readable as N-Quads, so excluded data could not be recovered from it, which is the log's purpose.
It now writes through `NQuadsStreamWriter`, the one N-Quads writer, and the hand-written copy is deleted.

## Fixed: `mercury-turtle --output-format` names every format

`--output-format` had its own copy of the format names, without `rdf` and `jsonld`, although convert writes RDF/XML
and JSON-LD since 1.8.37. It now reads the name as a file extension is read, through the new
`RdfEngine.DetermineFormatFromExtension`. The six names are `nt`, `nq`, `ttl`, `trig`, `rdf` and `jsonld`, and an
unknown name is an error that lists them.

## Tests

- **11 new tests,** inline, one per writer, each reading bytes: the SPARQL HTTP server (SELECT, ASK, CONSTRUCT), Solid
  (resource and container), the metrics listener (stream and file), the attach pipe (server and client), the Turtle
  tool's output file (which must then validate), and the audit log's exact content.
- **All 11 fail on the code before.** The pipe tests show EF BB BF before the text.
- Full suite on omega: 6,616 tests, 0 failed, 169 skipped. W3C unchanged.
