# Sky Omega 1.8.16 — DrHook: VSTest tests sync on the target, not the clock

**Released:** 2026-10-26
**Version bump:** `Directory.Build.props` → 1.8.16 (with these notes)
**Predecessor:** [Sky Omega 1.8.15](1.8.15.md) — Tests run on Microsoft.Testing.Platform.

## Headline

Two DrHook integration tests failed every run on elite (Linux x64, 4 cores) and passed elsewhere. Both slept 500 ms
after attaching to a VSTest testhost and then ended the debug session, assuming the target's test was done by then.
On elite it wasn't. Ending the session sent SIGTERM to a testhost still in its startup handshake with vstest.console.
A testhost that dies there makes vstest.console wait out its full 90 s connection timeout, so `dotnet test` didn't
exit within the tests' 10 s window. Faster machines happened to land the kill after the handshake.

Both tests now wait for the target to reach its test method instead of waiting a fixed time. See
[finding 94](../../poc/drhook-engine/findings/94-vstest-dispose-during-handshake.md).

## Fixed

- **`AttachAndOwn_VstestTestHost_BriefWork_NaturalExit`** now runs to a breakpoint in the target's `[Fact]`, resumes,
  and waits for the testhost to exit by itself. Before, the testhost never exited naturally on any machine: it was
  always killed, often while parked at the VSTEST_HOST_DEBUG hold. The test now also checks that `dotnet test`
  returns exit code 0.
- **`AttachAndOwn_VstestTestHost_PauseThenDisposeWithoutResume_WorkerSilentBreakOnly`** runs to the same breakpoint,
  then pauses inside the running `[Fact]` and disposes without resuming, which is the case it covers.

## Changed

- The VSTest target's `IdleFact.RunBriefObservableWork` carries a `TEST_RUNNING_HERE` marker on its first statement.
  The tests set a line breakpoint there. It stays pending until the test assembly loads, and DrHook binds it then.
- `IntegrationTargetPaths.VstestTargetSource()` resolves the target's `IdleFact.cs`.

## Validation

- **elite (Linux x64, Ubuntu 26.04):** integration suite 17/17 in five runs in a row, 37 s each (was 58 s with the
  two failing). Full `dotnet test`: 5,005 tests, 4,999 passed, 0 failed, 6 skipped. No leftover processes.
- **omega (macOS, M5):** integration suite 17/17 in three runs in a row.

## Known issues

Carried over from [1.8.15](1.8.15.md): NCrunch is unverified with xunit.v3, and README's SPARQL `--filter` examples
match no tests. The 1.8.15 issue about two VSTest tests failing on elite is fixed here.
