# Sky Omega 1.8.26 — Mercury: a query's WHERE is parsed once

**Released:** 2026-10-28
**Version bump:** `Directory.Build.props` → 1.8.26 (with these notes)
**Predecessor:** [Sky Omega 1.8.25](1.8.25.md) — Mercury: no silent drops, LIMIT 0, one route for every WHERE.

## Headline

Mercury parsed a query's WHERE twice: once into a flat structure of fixed-size slots, and once into the pattern tree
that executes it. Routing, EXPLAIN, the parse-time checks and the sub-SELECT read the flat copy, so what they saw could
differ from what ran. [ADR-055](../adrs/mercury/ADR-055-query-where-one-parse.md) makes the pattern tree the only
parse of a WHERE. The flat parser and everything that read it are deleted.

Most of the fixes below were cases where the two copies disagreed, and several were wrong results with no error. A
VALUES clause kept 16 values and dropped the rest. A VALUES after an ASK or a CONSTRUCT was ignored. The release
removes about 7,600 lines, and a simple SELECT now needs 23 KB of stack instead of 182 KB.

## Fixed

- **VALUES dropped data without an error.** Every VALUES kept at most 4 variables and 16 values; `VALUES ?x { 1 … 20 }`
  returned 16 rows. VALUES is now read straight from the query text, with no size limit, by one reader the parser and
  the executor share.
- **Valid queries failed to parse.** A top-level 3-way UNION, a GRAPH inside a nested group, and a GRAPH as a UNION
  branch were syntax errors, because only the flat parser rejected them.
- **A VALUES after ASK, CONSTRUCT or DESCRIBE was ignored.** Only SELECT read one: `ASK { ?s <p> ?o } VALUES ?s { <other> }`
  was true, and a CONSTRUCT ignored the rows its VALUES excluded.
- **Text after the end of a query was ignored.** A stray `}`, a second VALUES or any other text is now a syntax error.
  The REPL removes its `;` terminator itself.
- **Smaller VALUES fixes:**
  - an empty trailing `VALUES ?x { }` was ignored; it now leaves no solutions, as the spec requires;
  - `1e3`, `'single'` and `"""long"""` were syntax errors inside VALUES;
  - a malformed VALUES could be accepted: missing braces or variables, a blank node or variable as a value, or rows
    of the wrong size;
  - `VALUES $x` did not join with `?x`.
- **Sub-SELECT fixes:**
  - a `{` in its projection, as in `(CONCAT("{", ?o) AS ?y)`, made the executor run the expression text as the WHERE;
  - `SELECT *` lost every variable after a `}` inside a string in its WHERE;
  - it read only one HAVING condition, so `HAVING (a) (b)` was a syntax error;
  - it accepted a projected variable that was not grouped, and `SELECT *` with GROUP BY.
- **BIND could rebind a variable that an earlier sub-SELECT projects** (SPARQL 1.1 §18.2.1).
- **EXPLAIN drew a different plan from the one that ran.** Every plan showed `LIMIT 0`, an OPTIONAL's FILTER was drawn
  at the outer level, FILTER EXISTS was left out, GRAPH, MINUS and sub-SELECT were drawn empty, and a property path
  was drawn as a join. EXPLAIN now draws the pattern tree, with three new operators: `⇝` PathScan, `∃` Exists and
  `∄` NotExists.
- **CONSTRUCT WHERE accepted a property path**, which [52] TriplesTemplate does not allow, and could write nothing.
- **ASK rejected a solution modifier**, which [12] AskQuery allows. DESCRIBE now reads its list of variables and IRIs.
- **Install scripts:** `install-tools` builds before it packs, so a pack can't pick up a stale Debug assembly.

## Changed

- Removed: the flat WHERE parser (20 methods), the sub-SELECT's own body parser, and three copies of the VALUES parser.
  Also removed: QueryResults' flat-parse evaluators (58 methods), FilterAnalyzer's flat pushdown, QueryBuffer's
  WHERE-derived members, and the test-only execution entries.
- A sub-SELECT's WHERE is the child of its header in the pattern tree, parsed once with the rest of the query. Its
  modifiers and trailing VALUES are parsed by the same code as a query's.
- Stack use, measured with `tools/probes/stack` (Release, arm64):

  | Query | Before | After |
  |---|---|---|
  | Simple SELECT | 182 KB | 23 KB |
  | 10 nested groups | 371 KB | 39 KB |

  `ParseSelectQuery`'s frame shrank from 53 KB to 6.5 KB.
- A WHERE without `{` is a syntax error.
- **Linux:** run Sky Omega on Microsoft's .NET build, not Ubuntu's `dotnet-runtime-10.0`, which links the system
  `libunwind` and intermittently aborts with `Internal CLR error. (0x80131506)`. See the
  [Linux .NET runbook](../operations/runbook-linux-dotnet-runtime.md).

## Known issues

- **DESCRIBE still describes nothing through the facade.** It now reads its targets but does not yet use them
  ([ADR-055](../adrs/mercury/ADR-055-query-where-one-parse.md) D3).
- **A sub-SELECT's `SELECT *` finds its variables by scanning the text**, and misses `$x` variables (ADR-055 D7).
- **Mercury's W3C conformance runs only the SPARQL 1.1 manifests.** The 483 SPARQL 1.0 tests in the submodule are not
  run.
- **DISTINCT compares rows by a 32-bit hash**, so two different rows could be merged as duplicates. This is inferred
  from the code and has not been reproduced.
- **`INSERT DATA` stores a bare number such as `1` in a different form from a WHERE's `1`**
  ([ADR-053](../adrs/mercury/ADR-053-one-rdf-term-one-atom.md)).
- Carried over: on Linux, one debugger thread leaks per ended DrHook session; Windows lacks `RequestExit`.
