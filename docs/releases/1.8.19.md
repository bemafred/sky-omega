# Sky Omega 1.8.19 — DrHook on Windows arm64: the full suite passes

**Released:** 2026-10-26
**Version bump:** `Directory.Build.props` → 1.8.19 (with these notes)
**Predecessor:** [Sky Omega 1.8.18](1.8.18.md) — Mercury on Windows: presized files are sparse; first Windows arm64 run.

## Headline

The whole solution's `dotnet test` passes on Windows for the first time: on omega-windows (Windows 11 arm64), 5,011
tests, 0 failed, 13 skipped.

The DrHook engine needed no change. On its first run on Windows, before any fix, the integration tests that start
their target through `DebugSession.Launch` already passed: launch, breakpoint bind and removal, a compiled condition
evaluated without func-eval, and a state snapshot. The 12 failures were all in the test harness, which started every
target under `/bin/bash` ([finding 96](../../poc/drhook-engine/findings/96-windows-arm64-first-run.md)).

## Fixed

- **DrHook integration targets could not start on Windows.** `TargetSpawn` ran each target under `/bin/bash` for two
  POSIX reasons: the dual-reaper race (finding 87) and killing a run by process group, orphans included (finding 90).
  Windows has neither reaping nor process groups. There the target is a direct `Process.Start` child, and a Job
  Object takes the place of the process group.

## Added

- **`SpawnedProcessJob`** (integration-test harness, Windows). Before its first spawn, the test host puts itself into
  a `KILL_ON_JOB_CLOSE` Job Object, so every process the harness starts, and every process those start, joins the job
  inside CreateProcess. Assigning each target after it starts would let its own early children escape.
  `KillAllButHost` ends a run, and also runs at `[AssemblyCleanup]`. If the host dies, the job kills what is left.
- **`SpawnedProcessJobTest`**: an orphaned grandchild (`cmd` starts `ping`, then only `cmd` is killed) is still killed
  with the job.

## Validation

- **omega-windows (Windows 11 arm64):** full `dotnet test`: 5,011 total, 4,998 passed, 13 skipped, 0 failed. DrHook
  integration 16 passed, 2 skipped (POSIX-only), 0 failed in 3 of 3 runs, with no test processes left afterwards.
- **omega (macOS, M5):** DrHook integration 17 passed, 1 skipped (the Windows-only harness test).

## Known issues

- **Still missing in the engine on Windows** (from its code, not yet exercised):
  - A launched target inherits the debugger's console, so under `drhook-mcp` its output would land on the MCP channel.
  - Launch with environment overrides throws `PlatformNotSupportedException`.
  - `RequestExit` (the graceful stop) is not implemented.
- The probe corpus and `drhook-mcp` have not run on Windows yet, and nothing has run on Windows x64
  ([ADR-007](../adrs/drhook/ADR-007-teardown-concurrency-test-debug.md) Phase 9).
- Carried over: `dotnet test` does not show xunit's diagnostic messages; `dotnet test` exits 0 when its front end gets
  SIGTERM; NCrunch is unverified with xunit.v3.
